# 微信 4.1.9.30 UIA 兼容 Spec

状态：已批准

## Background

MewCode 微信机器人当前仅接受微信 `4.0.5.15`。该版本能够暴露机器人所需的 Windows UI Automation 控件，但部分微信账号已经被服务端拒绝登录并提示版本过低。

微信 `4.1.9.30` 在 Windows 讲述人先于微信启动并完成无障碍激活后，同样能够暴露完整、可操作的 UI Automation 控件树。讲述人未激活时，该版本只暴露不可用于聊天自动化的窗口外壳。

本次改动需要在保留现有 `4.0.5.15` 支持的同时，让机器人安全支持已激活无障碍能力的 `4.1.9.30`，并在无障碍控件树不可用时给出明确、可执行的错误提示。

## Goals

- 同时支持微信 `4.0.5.15` 和 `4.1.9.30`。
- 复用两个版本共同暴露的现有 UI Automation 控件语义。
- 在微信只暴露窗口外壳时快速、安全地拒绝启动机器人。
- 明确提示用户先启动 Windows 讲述人并重启微信。
- 保持现有消息读取、会话切换、目标复核和文字发送行为不变。

## Functional Requirements

- F1：机器人必须接受且仅接受微信 `4.0.5.15` 和 `4.1.9.30` 作为本次保证兼容的客户端版本。
- F2：启动和只读探测都必须确认当前只有一个可用的微信主窗口，并且机器人依赖的会话列表、消息列表和聊天输入区域均唯一存在。
- F3：微信正在运行但未暴露可操作的 UI Automation 控件树时，程序必须明确提示“请先启动 Windows 讲述人并重启微信”，不得仅报告“未找到窗口”或等待超时。
- F4：程序不得自动启动或关闭 Windows 讲述人，不得自动重启微信，不得修改系统无障碍设置，也不得修改微信文件或进程内存。
- F5：只读探测成功时必须输出实际微信版本及必要控件信息，不得读取后自动发送消息。
- F6：不受支持的微信版本必须继续被安全拒绝，并在错误中列出本次支持的两个版本。
- F7：版本适配不得改变现有白名单、消息过滤、消息去重、会话隔离、发送前目标复核和无鼠标发送规则。

## Non-Functional Requirements

- N1：版本判断和错误提示必须可在不启动真实微信的单元测试中验证。
- N2：真实微信验收只执行只读探测，不自动向任何联系人发送测试消息。
- N3：未激活 UI Automation 时必须快速失败，不进行无限重试或高频扫描。
- N4：改动应保持最小范围，不新增依赖或另一套微信自动化实现。
- N5：现有 MewCode TUI 和微信机器人自动化测试不得回退。

## Out of Scope

- 自动启动、关闭或控制 Windows 讲述人。
- 自动重启、升级或降级微信。
- 绕过微信“版本过低”登录限制。
- 修改微信客户端文件、注入代码或热修改进程内存。
- 为 `4.0.5.15` 和 `4.1.9.30` 之外的微信版本提供兼容保证。
- 新增 OCR、坐标点击、数据库读取或其他 UI Automation 兜底方案。
- 改变现有机器人聊天能力、人物角色、消息协议或安全权限。

## Acceptance Criteria

- AC1：微信 `4.0.5.15` 暴露完整 UI Automation 控件树时，只读探测和机器人启动继续通过。
- AC2：微信 `4.1.9.30` 在讲述人激活后，只读探测成功并唯一识别会话列表、消息列表和聊天输入区域。
- AC3：微信 `4.1.9.30` 只暴露窗口外壳时，程序快速失败并提示“请先启动 Windows 讲述人并重启微信”。
- AC4：运行其他微信版本时，程序拒绝启动并明确列出支持 `4.0.5.15` 和 `4.1.9.30`。
- AC5：失败路径不会启动讲述人、重启微信、修改系统设置或修改微信进程。
- AC6：现有 UI Automation、微信配置、机器人运行时和全量自动化测试继续通过。
- AC7：真实微信 `4.1.9.30` 的只读探测输出实际版本和三个必要控件，且不发送任何消息。
