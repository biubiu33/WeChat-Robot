# 微信 4.0.5.15 单版本兼容 Spec

状态：已批准（第二次修订）

## Background

微信机器人原以微信桌面客户端 4.1.12.55 的 UI Automation 结构为基准，但本机该版本没有暴露可用控件树。微信 4.0.5.15 已实测暴露完整控件树，但会话项、未读提示和搜索结果与原基准不同：程序虽然能启动，却在发现未读消息后无法切换到精确联系人，并只记录异常类型。需要以 4.0.5.15 的实际控件行为重做现有 V1 普通好友文字收发适配。

## Goals

- 将微信机器人的唯一受支持客户端版本改为 4.0.5.15。
- 保持现有消息监听、目标复核和安全发送行为不变。
- 让版本提示、使用说明和自动化验证保持一致。

## Functional Requirements

- F1：微信机器人只接受版本 4.0.5.15。
- F2：包括原兼容版本在内的其他微信版本必须在启动或探测时被明确拒绝。
- F3：只读探测应继续验证唯一主窗口、会话列表、消息列表和输入框。
- F4：现有白名单、私聊过滤、消息去重、会话切换和发送前目标复核行为不得改变。
- F5：用户文档和示例配置必须只声明支持 4.0.5.15。
- F6：白名单普通好友出现未读文字消息时，系统应从该版本的组合会话信息中识别精确联系人和未读数。
- F7：系统应在搜索结果缺少联系人专属内部标识时，仍能通过精确显示名和唯一结果安全切换会话；重名或多结果时必须拒绝。
- F8：UI Automation 观察失败时，日志应包含可理解的具体原因，而不应只记录异常类型。

## Non-Functional Requirements

- N1：不新增依赖，不引入多版本兼容配置或抽象层。
- N2：自动化测试不得连接或操作真实微信。
- N3：真实客户端验收默认只读，不主动发送消息。
- N4：现有微信专项自动化测试不得回退。

## Out of Scope

- 同时支持多个微信版本。
- 兼容 4.1.12.55 或其他 4.x 版本。
- 使用坐标点击、截图、OCR 或视觉模型替代 UI Automation。
- 改变机器人业务行为、权限边界或消息处理流程。
- 自动向真实好友发送测试消息。
- 扩展群聊、图片、语音、文件或坐标点击能力。
- 构建跨微信版本的通用控件适配框架。

## Acceptance Criteria

- AC1：4.0.5.15 不再触发“不支持的微信版本”错误。
- AC2：非 4.0.5.15 版本仍被明确拒绝，并显示唯一支持版本。
- AC3：在普通好友聊天页执行只读探测时，主窗口和三个必要控件均能被唯一识别。
- AC4：微信专项自动化测试全部通过。
- AC5：README 和示例配置中不再把 4.1.12.55 声明为兼容版本。
- AC6：4.0.5.15 中白名单好友产生未读消息后，监听器识别精确联系人、切换到唯一搜索结果并读取文字消息。
- AC7：搜索结果重名、缺失或切换后标题不符时安全失败，不向其他联系人发送内容。
- AC8：UI Automation 观察失败日志包含具体失败原因，可区分搜索结果缺失、控件缺失和目标复核失败。
