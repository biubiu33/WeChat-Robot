# MewCode 微信自然对话节奏与分段回复 Spec

状态：已批准（2026-08-20）

## Background

MewCode 微信机器人已经实现每好友 7 秒意图合并、闲聊气泡协议、专业纯文本回答、自然打断和工具阶段通知。微信 `4.0.5.15` 的真实 UIA 探测与消息发送已经恢复正常。

真实闲聊验证发现，模型面对由多条用户消息组成的日常对话时，仍可能把多个完整句子放进一个气泡。现有规则把多气泡表达描述为可选行为，模型没有输出 `<|bubble|>`，因此发送层只能忠实发送一个段落。当前基础角色也只是通用“个人助手”，缺少稳定、自然的朋友式语气。

本次修订在保留既有技术和安全边界的基础上，明确全局朋友型角色，并把“多句闲聊按语义拆成多个气泡”从建议提升为强制行为。

## Goals

- 将同一好友短时间内连续发送的消息合并为一个完整意图后再处理。
- 让闲聊回复表现为有顺序的多个简短语义气泡。
- 让机器人保持温暖、活泼、会适度开玩笑的年轻朋友式语气。
- 让专业问题保留完整、清晰的长文本表达能力，不被闲聊规则切碎。
- 在调用工具时自然告知好友当前正在进行的工作。
- 允许同一好友用新消息自然打断旧任务和尚未发送的旧回复。
- 所有可见回复使用适合微信的纯文本，不暴露 Markdown 包装字符。

## Functional Requirements

- F1：系统必须为每名好友独立收集连续入站消息；从该好友最后一条消息开始连续 7 秒没有新消息后，才把本批消息视为一个完整意图。
- F2：同一好友在 7 秒收集期内继续发送消息时，系统必须保留消息原始顺序、合并全部消息并重新开始 7 秒计时，不得逐条抢答或静默丢弃较早消息。
- F3：完成收集的好友意图必须进入现有全局先进先出队列；不同好友的模型任务和微信发送仍保持全局串行，不得交错发送。
- F4：某好友的意图已进入全局队列但尚未开始处理时，如果该好友又发来消息，旧队列项必须失效；旧消息与新消息重新组成待收集意图，并重新等待 7 秒。
- F5：系统必须根据当前消息和该好友的对话上下文，自行选择自然闲聊表达或专业回答表达；不得为此额外发起一次独立的意图分类模型请求。
- F6：闲聊回复包含多个完整句子或多个独立语义点时，必须按自然口语边界拆成多个语义气泡，并使用专用标记 `<|bubble|>` 表达气泡边界；该标记不得发送给好友。
- F7：闲聊回复每轮最多发送 7 个语义气泡。空白气泡必须忽略；超过上限的内容必须合并进最后一个气泡，不得因限制而丢失回答内容。
- F8：闲聊气泡必须保持模型给出的顺序逐条发送。相邻气泡之间使用与下一条文字长度相关的短暂间隔，并始终限制在 0.4 秒至 2 秒之间。
- F9：专业回答默认作为完整纯文本发送，不因正文中的反斜线、Windows 路径、正则表达式、公式或代码字符而拆分。只有超过微信单条消息长度限制时，才按自然段安全拆成多条传输消息。
- F10：专业回答因长度产生的传输拆分不受闲聊 7 气泡上限约束，也不模拟闲聊逐字输入节奏；拆分不得破坏代码、链接或正文顺序。
- F11：同一好友在模型生成、工具执行或气泡发送期间发来普通新消息时，系统必须立即取消该好友当前任务和所有尚未发送的旧气泡，把新消息放入新的 7 秒收集窗口。已经成功发送的消息不撤回，也不额外发送取消提示。
- F12：其他好友的新消息不得取消当前好友任务，只按各自的 7 秒收集状态进入全局队列。
- F13：系统不再提供 `/cancel` 本地指令；取消只由同一好友的新普通消息触发。
- F14：每次进入一个新的工具工作阶段时，系统必须先发送一条简短自然的状态消息，说明正在进行的工作。状态消息不得暴露内部工具名称、参数、调用栈或实现细节。
- F15：同一工具工作阶段只发送一次状态消息。一个网页查询阶段内的搜索和后续网页读取不得逐次提示；只有工具目的发生明确变化时才可以发送新的状态消息。
- F16：已经发出的工具状态消息无法撤回；后续收到同一好友新消息时，系统必须停止当前工具和后续旧回复，并按新意图重新处理。
- F17：网页查询的最终内容按“工具状态、专业回答、网页来源”的顺序呈现。网页来源必须独占本轮最后一条消息，不得混入前面的闲聊气泡或专业正文。
- F18：所有好友可见文本必须避免 Markdown 包装，包括用于加粗或斜体的成对标记、Markdown 标题前缀、三反引号代码围栏、引用包装和 Markdown 链接包装。
- F19：移除 Markdown 包装时必须保留正文和代码的原始语义字符。代码中的 `#`、`*`、`**`、反斜线、下划线及其他语法字符不得被全局删除或改写；代码围栏可以移除，但围栏内代码必须完整保留。
- F20：专业回答应使用普通段落、空行和自然的中文编号组织内容；不得为了规避 Markdown 而把内容压缩成难以阅读的一整行。
- F21：工具失败、模型失败或发送失败时，系统必须使用简短纯文本说明当前结果；不得向好友暴露异常栈、密钥、路径或内部错误详情。
- F22：后续对话上下文必须与好友实际看到的内容一致。被新消息取消且尚未发送的旧气泡不得在后续轮次中被当作已经告知好友的内容。
- F23：微信侧使用统一的年轻朋友型角色：温暖、活泼、自然关心好友，可以适度开玩笑，但不使用恋爱关系、亲属关系或其他未经用户确认的亲密身份设定。
- F24：角色不得虚构自己真实上学、工作、购物、出行或拥有现实生活经历；需要表达陪伴感时应以助手当前对话和能够确认的上下文为基础。
- F25：被询问身份时必须如实说明自己是 AI 助手，不得伪装成人类；角色语气不得削弱现有安全、隐私和工具权限边界。
- F26：仅包含“嗯”“好”“哈哈哈哈哈哈”等简短确认、情绪或笑声，或者本身只有一个完整语义点的闲聊回答，可以只发送一个气泡，不得为了满足形式强行拆碎词语或短句。

## Non-Functional Requirements

- N1：好友会话、待收集消息、取消状态和回复内容必须严格隔离，不得跨好友合并或泄露。
- N2：微信 UI 操作继续保持全局串行，并在每条消息发送前验证目标好友，不能因自然节奏功能增加误发风险。
- N3：意图表达和气泡生成复用当前回答模型，不增加独立分类模型、第三方队列或新的运行依赖。
- N4：7 秒收集等待和 0.4 至 2 秒发送间隔必须可被新消息或程序关闭及时唤醒，不能使用不可中断的阻塞等待。
- N5：消息合并、失效队列项、重复 UI 事件和任务取消不得导致同一用户内容被重复回答。
- N6：现有微信好友白名单、只读公共信息工具范围、本地权限隔离、来源净化和全局 FIFO 安全边界必须保持不变。

## Out of Scope

- 微信原生“正在输入”状态或键盘输入动画。
- 微信原生引用回复和上下文指代识别。
- 图片、语音、视频和文件的新增输入输出能力。
- 好友级差异化人设、Emoji 偏好和长期记忆配置。
- 主动消息、群聊和定时提醒。
- `/cancel` 或其他显式取消命令。
- 为意图分类训练、调用或部署独立模型。

## Acceptance Criteria

- AC1：同一好友连续发送多条消息时，最后一条到达后的前 7 秒内不调用模型；静默满 7 秒后只产生一次合并任务，消息顺序和内容完整。
- AC2：已就绪但尚未处理的好友任务收到补充消息后不会被执行；新旧内容重新等待 7 秒并只回答一次。
- AC3：多个好友先后完成 7 秒收集时，任务按进入全局队列的顺序处理，任一好友的多条出站消息都不与其他好友交错。
- AC4：闲聊示例输出中的 `<|bubble|>` 被拆成有序气泡且不会出现在微信消息中；不足 7 条正常发送，超过 7 条时最多发送 7 条且内容不丢失。
- AC5：闲聊相邻气泡的观察间隔均不短于 0.4 秒且不长于 2 秒，较长的下一条消息在上限内获得不短于较短消息的等待时间。
- AC6：包含 `C:\Users\name`、正则转义、公式或代码反斜线的专业回答不会被错误拆成闲聊气泡。
- AC7：超过微信单条长度限制的专业回答按自然边界有序拆分，重组后语义内容与原回答一致，且不受 7 条限制。
- AC8：同一好友在模型、工具或发送阶段发来新消息后，当前工作及时停止，剩余旧气泡不再发送；新消息静默 7 秒后形成新任务，且不出现自动取消提示。
- AC9：其他好友发来的消息不会取消当前任务，只会独立等待并按全局 FIFO 处理。
- AC10：一次网页查询即使执行搜索并读取多个网页，也只发送一次对应阶段状态；切换到不同工具目的时可以再发送一次新的状态。
- AC11：网页查询最终可见顺序为状态消息、专业正文、最后的独立来源消息；失败时仍给出纯文本结果说明，不编造来源。
- AC12：普通回复中不出现 Markdown 加粗、标题、引用、链接包装或三反引号围栏；示例代码移除围栏后仍保持 `#`、`*`、`**`、反斜线和缩进等有效内容。
- AC13：新消息打断部分发送后，下一轮模型只能把已经实际发送的气泡视为历史回复，不会引用未发送的旧内容。
- AC14：`/cancel` 不再触发本地取消确认或专用控制流程。
- AC15：现有微信白名单、去重、目标复核、好友 Session 隔离、只读工具边界及来源净化相关回归验证继续通过。
- AC16：给定日常闲聊“今天忙吗”和“我好无聊”，回复“哈哈今天不算特别忙，就是回答了一堆问题。你呢，怎么无聊起来了，今天没安排点事做？”应表达为四个有序语义气泡：“哈哈今天不算特别忙”“就是回答了一堆问题”“你呢，怎么无聊起来了”“今天没安排点事做？”。
- AC17：给定适合简短回应的闲聊，模型可以只输出“嗯”或“哈哈哈哈哈哈”，发送层只产生一个气泡，不追加空气泡或机械扩写。
- AC18：日常对话体现温暖、活泼、有分寸的朋友式语气，不把任何好友默认称作男朋友或女朋友，不编造现实经历；身份追问仍如实回答 AI 助手。
