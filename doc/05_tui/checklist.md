# TUI 展示优化 Checklist

> 每一项必须通过运行代码或观察实际行为验证。此清单只覆盖 TUI 展示优化，不改变 Agent 核心逻辑。

## 实现完整性

- [x] 用户回合高亮：每个用户问题显示为独立高亮条目，包含用户标识和完整文本，连续三轮之间有稳定间距。（验证：`tests/test_tui.py` 创建三轮消息并断言用户条目 class、文本和顺序。）(AC1/F1)
- [x] 语义化时间线：助手、工具调用/结果、错误和通知均有不同且一致的语义 class 或样式。（验证：`tests/test_tui.py` 检查条目 class 和成功/失败文本。）(AC2/F2)
- [x] 工具结果默认折叠：工具结果标题显示工具名、状态与安全摘要，初始为收起状态；点击或调用展开后可查看截断摘要，再次操作可收起。（验证：`tests/test_tui.py` 断言 `Collapsible.collapsed` 切换及摘要内容。）(AC3/F3)
- [x] 安全工具摘要：`bash` 标题显示命令，`write_file` 标题不出现 `content` 正文，展开结果仍使用既有截断限制。（验证：`tests/test_tui.py` 传入敏感写入参数和超长结果断言不可见/截断。）(AC3/N4)
- [x] 固定多行输入区：时间线增长时输入框与状态栏仍位于底部；Enter 提交和 Alt+Enter 换行行为保持。（验证：窄尺寸 `run_test()` 与现有输入测试。）(AC4/N1)
- [x] 输入恢复：正常完成、Provider 错误和 Esc 取消后输入框均可编辑且获得焦点。（验证：现有与新增 `tests/test_tui.py` 场景通过。）(AC4/F4)
- [x] 临时活动区：流式回复、工具运行和等待状态显示当前内容、耗时和迭代；回合完成、错误或取消后清空。（验证：模拟 Provider/工具事件，断言 `#streaming` 更新与清空。）(AC6/F6)

## 集成与边界

- [x] 条件自动滚动：时间线处于底部时追加条目自动跟随；手动滚到历史位置后追加不改变 `scroll_y`；回到底部后恢复跟随。（验证：`Timeline` 的 Textual 测试。）(AC5/F5)
- [x] 工具事件顺序：连续只读工具、写工具和工具结果在时间线中仍按 Agent 事件顺序显示。（验证：既有多工具 Agent/TUI 回归测试。）(AC6/AC7)
- [x] 普通工作流：多轮对话、`/plan`、`/do`、token 状态栏、取消和错误恢复保持原行为。（验证：`tests/test_tui.py` 13 项通过；全量回归的唯一失败为既有系统提示标题断言不匹配，详见下方记录。）(AC7/F7)
- [x] 范围守卫：Agent、Provider、工具、Conversation 与系统提示模块没有功能改动；新增或修改文件仅位于 TUI、TUI 测试和 `doc/05_tui/`。（验证：审阅 `git diff --name-only`。）(F7)
- [x] 依赖守卫：未新增浏览器前端、外部 UI 框架或运行时依赖。（验证：审阅 `pyproject.toml` 与依赖锁定文件，如存在。）(N5)

## 端到端场景

- [ ] 三轮普通对话：连续提交三条中文消息，确认每轮用户问题高亮、助手回复顺序正确，输入区始终固定在底部。（验证：手工启动 TUI 观察。）
- [ ] 工具结果展开：执行包含 `bash`、`read_file` 或 `write_file` 的任务，确认工具标题安全、结果默认收起、鼠标点击后正确展开与收起。（验证：手工启动 TUI 观察。）
- [ ] 历史滚动：产生足够长的对话后向上滚动，继续让模型输出或执行工具，确认视图不跳到底部；主动回到底部后继续跟随。（验证：手工启动 TUI 观察。）
- [ ] 计划与取消：进入 `/plan` 后发送任务，再 Esc 取消；确认活动区清空、输入恢复、时间线保留取消提示，随后 `/do` 或普通消息仍可继续。（验证：手工启动 TUI 观察。）
- [ ] 窄终端：在较窄窗口运行并产生长工具结果，确认标题与输入区不重叠，默认折叠结果不撑开主时间线。（验证：手工调整终端宽度观察。）
