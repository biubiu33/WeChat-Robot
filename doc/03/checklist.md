# 工具系统 Checklist

> 每一项必须通过运行代码或观察行为验证。自动化测试不得调用真实 LLM API 或修改项目外的真实用户文件；真实 API 与 TUI 项目仅在具备对应 profile 时手工验收。

## 工具抽象与注册中心

- [ ] 默认注册中心恰好包含 `read_file`、`write_file`、`edit_file`、`bash`、`glob`、`grep` 六个工具，顺序稳定且可按名查找（验证：运行 `pytest tests/test_tool.py`）【AC1】
- [ ] 每个工具都提供非空名称、中文描述、完整参数 Schema 和统一异步执行入口（验证：注册中心单元测试）【AC1】
- [ ] OpenAI 与 Anthropic 的首次请求和续答请求均携带六个协议格式正确的工具定义（验证：mock 请求体集成测试）【AC1/F3】
- [ ] 重复注册、未知工具、非法 JSON、参数缺失或类型错误均返回结构化错误，不抛出未捕获异常（验证：注册中心单元测试）【F1/F9/N4】
- [ ] 工具内部发生未预期异常时，注册中心将异常转换为错误结果，会话编排仍可继续（验证：伪 Tool 单元测试）【F5/F9/N4】

## 文件工具

- [ ] 读取 UTF-8 文本时返回正确内容和稳定行号，中文内容不乱码（验证：`pytest tests/test_tool.py -k read_file`）【AC2】
- [ ] 读取不存在文件、目录、不可读文件或非 UTF-8 文件时返回可区分的结构化错误（验证：读文件边界测试）【AC2/F9】
- [ ] 写文件能创建新文件和缺失的父目录，并以 UTF-8 写入中文内容（验证：`pytest tests/test_tool.py -k write_file`）【AC3】
- [ ] 写入已有文件时按要求完整覆盖，返回路径与写入量摘要（验证：写文件覆盖测试）【AC3】
- [ ] 改文件在原文仅匹配一次时只替换该处，写回内容正确（验证：`pytest tests/test_tool.py -k edit_file`）【AC4】
- [ ] 改文件在原文匹配 0 次时返回“未找到匹配”类错误，不改动原文件（验证：改文件零匹配测试）【AC4/F9】
- [ ] 改文件在原文匹配多次时返回匹配数量与重试提示，不改动原文件（验证：改文件多匹配测试）【AC4/F9】
- [ ] 相对路径按 MewCode 启动目录解析，绝对路径可以访问启动目录之外的测试文件（验证：在临时目录树中调用文件工具）【最新版范围约束】

## 命令与搜索工具

- [ ] 正常命令返回 stdout、stderr 和退出码，命令实际工作目录与 MewCode 启动目录一致（验证：`pytest tests/test_tool.py -k bash`）【AC5】
- [ ] 非零退出命令返回错误结果，并保留 stdout、stderr 和非零退出码供模型判断（验证：命令失败测试）【AC5/F9】
- [ ] 超时命令在限制时间内被终止和回收，返回超时错误且测试进程不挂起（验证：短超时测试）【AC5/N1】
- [ ] Glob 使用 `**/*.py` 等模式返回正确文件，结果排序稳定且只包含文件（验证：`pytest tests/test_tool.py -k glob`）【AC6】
- [ ] Glob 支持可选搜索路径；无匹配时返回正常的空结果说明，不导致会话失败（验证：Glob 边界测试）【AC6/F9】
- [ ] Grep 返回 `文件:行号:内容` 命中位置，支持中文、指定路径和可选文件过滤模式（验证：`pytest tests/test_tool.py -k grep`）【AC6】
- [ ] Grep 遇到非法正则时返回结构化错误，遇到单个不可读或非 UTF-8 文件时跳过并继续搜索（验证：Grep 边界测试）【F9/N4】
- [ ] Grep 无命中时返回明确说明，程序和后续会话不受影响（验证：无命中测试）【F9】

## 流式协议适配

- [ ] OpenAI 正文增量保持流式输出，单个工具调用的名称与分片 JSON 参数能够完整拼接（验证：`pytest tests/test_llm_helpers.py -k openai`）【AC7】
- [ ] OpenAI 同一响应中的多个工具调用即使交错分片，也能按调用 index 正确还原顺序、ID、名称和参数（验证：伪 chunk 测试）【F4/F5】
- [ ] OpenAI assistant 工具调用和对应 `role=tool` 结果按正确 ID 写入续答请求（验证：mock 请求体测试）【AC8/F6】
- [ ] Anthropic 正文增量保持流式输出，thinking 增量不显示，完整 `tool_use` 块能还原 ID、名称和参数（验证：`pytest tests/test_llm_helpers.py -k anthropic`）【AC7】
- [ ] Anthropic 多个 `tool_use` 和对应的多个 `tool_result` 块按正确 ID 写入续答请求（验证：mock 请求体测试）【AC8/F6】
- [ ] Anthropic 普通首次请求遵循 profile 的 extended thinking 设置，含工具历史的续答关闭 thinking 且请求格式有效（验证：请求参数测试 + thinking profile 手测）【F4/F7】
- [ ] 空工具参数被归一为合法 JSON 对象；无法解析的工具 JSON 以可读错误结束当前请求，不显示崩溃堆栈（验证：协议边界测试）【N4】
- [ ] Provider 异常中的 API key 被替换或移除，不出现在测试输出和 TUI 错误信息中（验证：脱敏测试）【N6】

## Agent 单轮闭环

- [ ] 普通文本问题只触发一次模型请求，回复继续逐段产生并正确进入多轮历史（验证：`pytest tests/test_agent.py` 和普通聊天手测）【回归】
- [ ] “读取文件并总结”触发首次模型请求、一次工具执行、结果回灌、一次续答，并且最终答复体现文件内容（验证：Agent fake Provider 测试 + 真实 API 手测）【AC8】
- [ ] 一次模型响应中的多个工具调用严格按模型返回顺序执行，所有结果保存后才发起续答（验证：多工具顺序测试）【F5】
- [ ] 某个工具执行失败后，同批次后续工具仍然执行，成功与失败结果均一并回灌（验证：混合结果测试）【F5/F9】
- [ ] 工具调用、工具结果和最终 assistant 答复按实际顺序保存在会话历史中，后续用户问题仍携带这些上下文（验证：Conversation 与 Agent 测试）【F6】
- [ ] 续答阶段再次返回工具调用时不执行第二批工具，并以已有正文或明确的单轮上限提示结束（验证：Agent 上限测试）【AC9】
- [ ] Provider 首次请求或续答请求失败时，本轮以错误事件结束，TUI 恢复输入且下一条消息仍可提交（验证：错误事件测试 + TUI 手测）【N4】
- [ ] 退出时正在运行的流任务可被取消，不将取消显示为普通错误（验证：取消测试）【回归】

## TUI 与交互

- [ ] 工具开始执行时立即显示 `● 工具名(关键参数)` 和执行中状态，不等待工具结束才出现（验证：真实 TUI 观察）【AC11/N2】
- [ ] 工具结束后调用行与结果摘要按顺序进入 scrollback，向上滚动后仍可查看（验证：工具任务截图与滚动检查）【AC11】
- [ ] 文件内容、写入正文或超长命令不会完整出现在工具参数预览中；预览保持单行且有长度上限（验证：长参数渲染测试与 TUI 观察）【AC11/N5/N6】
- [ ] 成功结果与错误结果样式可区分，过长结果摘要被截断并明确标记（验证：视图渲染测试 + TUI 观察）【AC11/AC12】
- [ ] 模型流式回复、工具执行和搜索期间界面保持响应，可滚动并显示进行中状态（验证：运行慢命令和大目录搜索时操作 TUI）【N1/N2】
- [ ] 每轮成功或失败结束后输入框恢复可编辑并自动聚焦，连续发送至少三轮均正常（验证：连续对话手测）【AC12/回归】
- [ ] 工具前置正文、工具记录和最终答复各显示一次，不重复、不覆盖且顺序正确（验证：含 preamble 的工具任务手测）【F8】

## 体量与健壮性

- [ ] 超大文件读取受行数和体量上限控制，回灌内容带截断标记（验证：大文件测试）【AC13/N5】
- [ ] 超长命令输出受字符上限控制，stdout/stderr/退出码语义仍可辨认（验证：长输出测试）【AC13/N5】
- [ ] Glob/Grep 海量结果最多返回规定数量并标注截断，不撑爆上下文或 scrollback（验证：海量结果测试）【AC13/N5】
- [ ] 工具参数缺失、类型错误、非法路径、无效正则、命令失败和 JSON 解析失败均不产生未捕获堆栈（验证：全套错误测试）【AC12/N4】
- [ ] 工具失败后再发送普通问题能够获得正常回复，证明会话未中断（验证：真实 TUI 连续操作）【AC12】
