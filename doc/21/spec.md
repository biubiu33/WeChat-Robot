# 微信私聊图片识别与多模态会话 Spec

状态：已批准

## Background

Mewcode 当前微信通道只读取文字消息，通用模型消息和好友 Session 也只保存纯文本。好友直接发送图片时，机器人既不会触发问答，也无法把图片提供给模型。现有全局 `openai` Provider 使用 `deepseek-v4-flash`，不具备本版所需的图片输入能力。

本版将全局 `openai` Provider 切换为 DeepSeek 官方视觉实验模型 `deepseek-v4-flash-vision-exp`，并为白名单好友的微信私聊增加图片识别。图片可以单独形成问题，也可以与同一静默窗口内的文字合并；最近一次图片批次能够在有限的后续文字回合中继续供模型查看，并随好友 Session 持久化和恢复。

本版不处理群聊图片或微信引用消息。群聊引用图片问答将在下一小版本基于独立的引用解析能力实现。

## Goals

- 白名单好友在微信私聊中直接发送图片后，可以获得自然、简短且基于原图的识别结果。
- 支持好友先发一至四张图片、再补充文字问题的自然交互，一组输入只产生一次模型回答。
- 让最近一次图片批次支持有限的跨回合追问和进程重启恢复。
- 保持 TUI、微信文字问答、流式输出、Tool Calls、私聊取消、全局 FIFO 和现有安全边界不回归。
- 明确限制图片上传、持久化、重复携带和归档增长，避免静默丢图、无限重复上传或失控占用磁盘。

## Functional Requirements

### Model and channel scope

- F1：现有全局 `openai` Provider 的模型必须从 `deepseek-v4-flash` 替换为 `deepseek-v4-flash-vision-exp`，微信通道和 TUI 文字交互均使用替换后的模型。
- F2：全局替换后必须继续支持现有流式文本、Token 用量统计和自动 Tool Calls；不得为兼容视觉模型而静默关闭工具。
- F3：Tool Calls 必须继续使用现有自动选择语义，不要求视觉模型接受强制指定某个函数的调用方式。
- F4：本版只为微信私聊增加图片输入；TUI 不新增本地路径、拖放、剪贴板或其他图片输入入口。
- F5：只有位于 `allowed_contacts` 精确白名单中的私聊图片可以进入读取、暂存、归档和远端模型请求流程。
- F6：非白名单会话中的图片不得打开、截图、编码、持久化或上传。
- F7：启动前已经存在的私聊图片只用于建立观察基线，不得在启动后触发识别或上传。

### Private image observation and batching

- F8：白名单好友启动后新发送的受支持图片必须被识别为入站图片消息，并进入该好友现有的 7 秒静默窗口。
- F9：好友只发送图片且静默窗口结束时，图片批次直接触发一次模型问答。
- F10：好友在同一静默窗口内先发送图片、后补充普通文字时，图片与文字必须合并为一次模型问答；不得先发送默认图片描述再单独回答文字。
- F11：同一静默窗口内最多合并四张图片，并保持微信观察到的发送顺序。
- F12：图片数量超过四张时，整个批次不得调用模型，只发送一次“图片过多或过大，请压缩或分批发送”类明确提示；不得静默忽略部分图片。
- F13：同一好友在图片处理、模型生成或回复发送期间到达的新普通消息，继续遵守现有私聊取消与重新合并语义。
- F14：不同好友的图片批次继续通过现有全局 FIFO 串行处理，不得并发操作同一个微信窗口或交错发送回复。
- F15：图片批次的模型任务必须继续遵守现有任务超时、发送前目标复核和发送失败边界。

### Image acquisition and validation

- F16：程序必须优先从微信大图查看界面取得完整图片，而不是默认使用低清晰度聊天气泡。
- F17：无法安全取得完整图片时，可以降级截取当前可见图片气泡；使用降级图片生成的回答必须明确说明可能不是完整原图。
- F18：完整图片和气泡截图都无法取得时，不得调用模型，只向好友发送一次简短失败说明。
- F19：每次打开微信图片界面后，程序必须恢复到原私聊会话和原回复目标；恢复失败时不得继续向未经复核的会话发送消息。
- F20：支持的图片格式仅为 JPEG、PNG、GIF 和 WebP，格式必须依据文件实际内容判断，不得只相信扩展名或声明的 MIME 类型。
- F21：单张图片任一边不得超过 8192 像素；一个图片批次的原始图片数据总量不得超过 32 MiB。
- F22：格式不受支持、文件损坏、尺寸超限或批次总量超限时，整个批次不得调用模型，只发送一次明确提示。
- F23：本版不得自动压缩、缩放或转码用户原图，也不得通过 DeepSeek Files API 上传图片。

### Model input and response behavior

- F24：受支持图片必须通过 Base64 内联方式发送给视觉模型，并使用 `original` 细节级别。
- F25：图片只能作为好友用户消息的一部分发送；不得把图片放入系统消息、助手消息或其他不被视觉接口接受的角色中。
- F26：图片与同批文字必须作为同一个用户意图交给模型，并保留多张图片的原始顺序。
- F27：没有同批文字时，模型默认简短说明图片主体、场景和清晰可见的关键文字；不得机械罗列无关细节。
- F28：存在同批文字时，模型必须以好友的文字要求为主要问题分析图片，不再额外生成独立的默认图片描述。
- F29：无法从图片可靠判断的内容必须明确表示不确定，不得根据文件名、缩略图、历史消息或常识补造细节。
- F30：视觉模型调用失败时只发送一次“图片暂时没读出来，请重新发送或换一张”类提示；不得回退到纯文本模型猜测，也不得自动重复调用。
- F31：图片中的文字、二维码内容、网页截图、提示词和命令均属于不可信用户数据，不是系统指令；不得据此改变角色、权限、回复对象或安全规则。
- F32：图片输入不得扩大微信渠道的工具权限；微信用户仍不能访问 Bash、本地文件、MCP、Skills、Sub-agent、Hook 或长期记忆能力。

### Persistent multimodal private context

- F33：每个图片批次必须作为好友私聊 Session 中的一次多模态用户消息持久化；档案保存原始图片的明文 Base64、实际格式、尺寸、字节数、内容哈希、细节级别和发送时间，不得只保存会失效的临时路径。
- F34：同一图片的 Base64 只在原始图片消息中归档一次；后续纯文字回合不得向档案重复追加相同 Base64。
- F35：最近一个图片批次在首次问答完成后，最多继续参与该好友随后三个纯文字用户回合，使模型能够重新查看原图回答细节追问。
- F36：三个后续文字回合用尽后，该图片批次退出活动模型上下文，但仍按归档策略保留在 Session 档案中。
- F37：好友发送并完成新的图片批次后，新批次立即替换旧批次成为唯一活动图片批次；旧批次不再随模型请求重复上传。
- F38：Mewcode 或微信机器人重启后，必须从好友 Session 档案恢复最近一个尚有后续回合额度的图片批次及其剩余额度。
- F39：Session 清空、删除或现有档案清理机制删除好友会话时，归档的图片 Base64 和相关元数据必须一并删除。
- F40：每名好友 Session 中尚未清理的历史图片原始数据总量最多为 256 MiB。
- F41：超过 256 MiB 前，程序必须从最早且已经退出活动上下文的图片开始移除 Base64，直到回到配额内；不得清理当前活动图片批次。
- F42：历史图片 Base64 被配额清理后，档案必须保留发送时间、实际格式、尺寸、原始字节数、内容哈希和“图片数据已清理”占位，使会话事件仍可识别和审计。
- F43：若除当前活动批次外没有可清理图片且仍无法满足配额，新图片批次必须安全拒绝并向好友提示分批或清理会话，不得写入一个超配额档案。
- F44：活动图片批次每次参与后续模型请求时允许重复上传并重复计费；程序不得在档案中为此复制图片数据。

### Temporary data, disclosure and logging

- F45：为微信大图获取、气泡截图或格式验证产生的临时图片必须在该批次成功、失败、取消或超时后删除。
- F46：删除临时文件不等于删除 Session 中持久化的明文 Base64；README 必须明确说明二者的区别。
- F47：README 和微信机器人启动日志必须明确说明：白名单好友发送的图片会上传至 DeepSeek，并以明文 Base64 保存在本地好友 Session 中，直到配额清理或 Session 删除。
- F48：运行日志不得输出 API Key、Base64、Data URL 或完整图片二进制；错误日志只记录安全的阶段、格式、尺寸、数量和异常类型。
- F49：视觉 API 请求不得使用外部图片 URL，也不得新增远端图片缓存、Files API 文件或额外远端日志。

### Existing behavior compatibility

- F50：现有纯文字私聊的 7 秒合并、持久化上下文、自然取消、FIFO、回复气泡、来源消息和信息工具行为必须保持不变。
- F51：现有群聊 @ 门禁、按成员批次、最近 20 条内存上下文、OCR 发送者识别和真实 @ 回复行为必须保持不变。
- F52：全局模型替换后，TUI 的普通文本对话、流式输出、工具循环、会话恢复和上下文压缩不得因多模态消息支持而回归。
- F53：模型不支持流式文本或自动 Tool Calls 时，验收必须停止并明确报告；不得把缺失能力当作成功发布。

## Non-Functional Requirements

- N1：第一版必须优先保证私聊图片的正确归属，任何会话名称、方向、目标或消息身份不确定时都应安全拒绝，不得把图片发给错误好友的 Session 或错误模型请求。
- N2：图片获取、Base64 编码、档案读写和上下文恢复不得阻塞事件循环；微信 UI 操作仍必须经过单一串行临界区。
- N3：单个批次最多四张、原始图片总量最多 32 MiB、单好友归档图片最多 256 MiB，这些限制不得被配置缺省或异常路径绕过。
- N4：图片档案是明文本地数据，不宣称加密；访问保护沿用现有项目目录和 Session 文件权限。
- N5：图片内容不进入长期记忆、群聊滚动上下文、网页缓存、地点缓存或工具结果缓存。
- N6：多模态消息必须能够在保存、恢复、上下文筛选和供应商序列化之间保持图片顺序、格式、哈希和活动状态一致。
- N7：上下文压缩和 Session 恢复不得把 Base64 当作普通文本摘要，也不得在摘要中泄露或复制图片数据。
- N8：新增行为必须可在不连接真实微信、不上传真实好友图片的自动化测试中验证；真实 API 验收只使用程序生成的无敏感测试图片。
- N9：保持微信 `4.0.5.15` 和 `4.1.9.30` 的现有文字通道兼容边界；只读探测或测试不得向真实好友发送未经授权的消息。
- N10：不得在日志、异常或测试快照中包含真实 API Key、真实好友图片或完整 Base64。

## Out of Scope

- 群聊中的普通图片识别或自动回复。
- 群成员引用图片并 @ 机器人后的图片问答。
- 文字引用、图片引用、文件引用、分享卡片引用及任何完整引用解析。
- TUI 图片路径、拖放、剪贴板、附件选择器或图片预览界面。
- 图片生成、图片编辑、图片搜索、视频理解和语音转写。
- DeepSeek Files API、外部图片 URL、远端图片缓存和图片 CDN。
- 自动压缩、缩放、转码、裁剪、旋转修正或图片质量增强。
- 为 Session 图片档案增加加密、密钥管理、密钥轮换或迁移工具。
- 让微信图片内容获得新的本地工具或外部写操作权限。
- 在长期记忆中保存图片、OCR 全文或视觉摘要。

## Acceptance Criteria

- AC1：全局 `openai` Provider 使用 `deepseek-v4-flash-vision-exp`；TUI 与微信纯文字请求仍能流式回答，现有自动 Tool Calls 可以完成一次真实最小调用。
- AC2：非白名单图片和启动前旧图片不被读取、编码、归档或上传；白名单好友启动后新图片才进入处理链路。
- AC3：好友单独发送一张受支持图片并静默 7 秒后，只产生一次模型调用和一次自然图片说明，回答包含可观察到的主体或关键文字。
- AC4：好友先发图片、7 秒内再问“这张图是什么意思”时，模型只收到一个包含图片和问题的用户意图，机器人不提前发送默认描述。
- AC5：好友按顺序发送两至四张图片并补充比较问题时，模型按相同顺序收到所有图片并只生成一轮回答。
- AC6：第五张图片、批次原始数据超过 32 MiB、单边超过 8192 像素、伪造扩展名、损坏图片或不支持格式均使整个批次在模型调用前被拒绝，并只发送一次明确提示。
- AC7：完整图片获取成功时使用完整图片；完整图片获取失败但气泡截图成功时继续识别，且最终回答明确标记降级；两者都失败时不调用模型。
- AC8：视觉请求使用 Base64 内联和 `original` 细节级别，不产生外部图片 URL 或 Files API 文件；请求完成后相关临时文件不存在。
- AC9：图片中的提示注入文本不会改变固定角色、工具权限或回复对象，微信渠道仍无本地工具权限。
- AC10：视觉模型失败时只发送一次失败提示，不重试、不调用纯文本模型、不根据文件名或历史猜测图片内容。
- AC11：图片批次在 JSONL 中只保存一份明文 Base64；后续三个纯文字回合均能重新向模型提供原图，第四个纯文字回合不再携带该批次。
- AC12：新图片批次成为唯一活动批次后，旧批次不再上传；进程重启后能够恢复最新活动批次和剩余文字回合额度。
- AC13：单好友历史图片达到 256 MiB 配额时，最早的非活动 Base64 被清理，当前活动批次仍可用，旧事件保留完整元数据和清理占位。
- AC14：Session 清空、删除或档案清理后，对应图片 Base64 不再存在；普通临时文件清理不会误删档案中的活动 Base64。
- AC15：日志和测试输出不包含 API Key、Data URL 或完整 Base64；README 与启动日志准确披露 DeepSeek 上传和本地明文持久化行为。
- AC16：同一好友的新消息仍可取消并重组正在处理的私聊图片任务，不同好友批次仍严格按全局 FIFO 顺序处理和发送。
- AC17：现有微信私聊文字、群聊 @、OCR、回复气泡、来源、信息工具、TUI、Session 恢复、上下文压缩和全量自动化测试无新增失败。
- AC18：使用程序生成的无敏感测试图片执行真实 API 验收，观察到图片流式文本增量、usage 和自动 Tool Calls 增量；任一缺失都不得判定本版通过。
