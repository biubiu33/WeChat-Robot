# Skill 系统验收清单

> 每项均须通过运行代码、测试或可观察行为验证。

## Skill 格式与发现

- [ ] 单文件 Skill 和包含 `SKILL.md` 入口及辅助文件的目录型 Skill 均能被发现（验证：运行 `tests/test_skill_catalog.py` 中的格式和目录发现用例）。
- [ ] frontmatter 必须验证名称、说明、工具白名单、执行模式和 `fork_history: none`；可选模型可被接受，`{{args}}` 被确定性替换（验证：格式与参数替换单元测试通过）。
- [ ] 项目级覆盖用户级，用户级覆盖内置级；同名时只展示、加载和调用最高优先级定义（验证：优先级用例通过）。
- [ ] 单个无效入口产生含路径的诊断且不影响其他有效 Skill；同级重复名称有确定性诊断（验证：错误文件与重复名称用例通过）。
- [ ] 目录内容新增、修改或删除后会在下一次刷新时重新发现；刷新失败保留上一个有效目录与命令集（验证：热更新用例通过）。

## 两阶段提示词与激活

- [ ] 启动提示词只含每个有效 Skill 的名称和一句说明，不含任一 SOP 正文（验证：提示词测试中比对名称、说明与唯一 SOP 文本）。
- [ ] `load_skill` 能按名称加载 Skill、替换调用参数并报告未知名称或错误参数（验证：系统工具单元测试通过）。
- [ ] inline Skill 加载后，其完整 SOP 位于每次后续请求的动态环境上下文开头；多个活动 Skill 同时存在（验证：多轮 Agent 请求测试通过）。
- [ ] `/clear`、Provider 切换、会话恢复和应用退出后均不保留活动 inline Skill（验证：TUI 生命周期测试通过）。
- [ ] 活动 SOP 与动态环境长度被计入上下文预算与压缩判断（验证：上下文预算集成测试通过）。

## 执行模式与工具安全

- [ ] inline Skill 在主对话中运行，其用户输入、工具过程和结果保留在可见历史及 JSONL 会话归档（验证：TUI inline 场景测试通过）。
- [ ] fork Skill 的隔离 Agent 只接收当前调用参数，不接收主对话消息、主归档或主工具结果（验证：隔离执行测试检查收到的消息）。
- [ ] fork 完成后，主历史仅包含调用事件和结果摘要；隔离内部工具调用、工具结果和完整记录不回流（验证：fork 摘要回流测试通过）。
- [ ] fork 取消会终止隔离执行并使主对话保持可继续使用（验证：取消后追加普通用户回合的测试通过）。
- [ ] 活动 inline Skill 只暴露其白名单普通工具与系统级 Skill 工具；未暴露普通工具即使被模型伪造调用也被拒绝（验证：注册表和 Agent 白名单测试通过）。
- [ ] `load_skill` 不受活动 Skill 白名单影响；`install_skill` 不受白名单影响但仍受计划模式和权限引擎限制（验证：系统工具、计划模式和权限测试通过）。
- [ ] 生效 Skill 的白名单包含不存在普通工具时，应用在进入 TUI 前报出 Skill 名称和工具名称并终止启动（验证：CLI 启动校验测试通过）。
- [ ] 指定模型使用当前 Provider 的同协议、密钥和端点；多个活动 inline Skill 请求不同模型时拒绝后一次激活（验证：运行时与 Agent Provider 选择测试通过）。

## 命令与热更新

- [ ] 每个生效 Skill 自动注册为 `/<name>`，并在 `/help` 与命令补全中可见；与内置命令冲突时不覆盖内置命令（验证：命令注册和补全测试通过）。
- [ ] `/<name> 参数` 根据声明路由至 inline 或 fork，且不把原始 Slash 文本写入主对话历史（验证：命令和 TUI 路由测试通过）。
- [ ] `/skill` 显示有效 Skill 的名称、说明、来源、活动状态及诊断摘要，但不显示完整 SOP（验证：命令输出测试通过）。
- [ ] 安装或目录变更后，`/skill` 和 `/<name>` 命令列表无需重启应用即可更新（验证：TUI 热更新与补全测试通过）。

## 安装与内置样板

- [ ] 安装工具接受 HTTPS URL 与本地 ZIP，拒绝明文 HTTP、其他 URL 方案和非 ZIP 本地来源（验证：安装器来源测试通过）。
- [ ] ZIP 解压拒绝绝对路径、路径穿越和符号链接；安装过程不执行包内脚本，且不会写出用户级目标目录（验证：恶意 ZIP 与副作用测试通过）。
- [ ] 合法目录型 Skill 经过元数据和工具校验后原子安装到用户级位置；同名目标已存在时拒绝覆盖（验证：安装成功与已存在目标测试通过）。
- [ ] 内置 `commit`、`review`、`test` 均以目录型 Skill 被发现，可加载并遵守正常工具白名单规则；打包资源在 wheel 环境可读（验证：内置资源发现测试通过）。

## 集成与兼容性

- [ ] 普通 Agent、MCP、权限模式、计划模式、会话归档、恢复、上下文压缩、记忆和既有 Slash 命令行为未退化（验证：受影响模块测试组与全量测试通过）。
- [ ] 无 Skill 时，提示词、Provider 选择、工具定义和 TUI 交互维持既有行为（验证：既有 Agent、prompt、tool 和 TUI 测试通过）。
- [ ] 所有解析、运行时、安装、fork、命令和 TUI 行为均可在不连接真实 Provider 或启动交互式 TUI 的情况下测试（验证：新增测试使用替身 Provider/控制器并通过）。

## 构建与测试

- [ ] 全量测试通过（验证：`conda run -n mewcode python -m pytest -q`）。
- [ ] 源码和测试可编译（验证：`conda run -n mewcode python -m compileall -q src tests`）。
- [ ] Ruff 静态检查通过（验证：`conda run -n mewcode ruff check .`）。
- [ ] Ruff 格式检查通过（验证：`conda run -n mewcode ruff format --check .`）。

## 端到端场景

- [ ] 场景一：启动应用后 Agent 只见 `review` 的名称说明；模型调用 `load_skill` 并带入参数；下一 ReAct 请求包含渲染后的完整 SOP，且只看到 `review` 声明的普通工具和系统工具；`/clear` 后 SOP 与工具限制均消失（验证：端到端 Agent/TUI 集成测试）。
- [ ] 场景二：执行 `/test 指定测试目标`；隔离 Agent 只收到“指定测试目标”，完成后主时间线和会话归档仅有调用事件与简短摘要，随后可提交一条普通主对话消息并成功运行（验证：fork 集成测试）。
- [ ] 场景三：通过本地合法 ZIP 安装目录型 Skill；无需重启即可在 `/skill` 及补全中看到它并执行 `/<name>`；尝试 HTTP 来源与含 `../` 条目的 ZIP 均以可诊断错误失败（验证：安装、目录刷新和命令集成测试）。
