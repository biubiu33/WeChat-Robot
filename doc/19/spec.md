# 微信提示词文件化与原始回复日志 Spec

状态：已批准

## Background

微信机器人当前把角色设定和回复协议分别散落在配置与程序代码中。虽然回复协议已经要求闲聊使用 `<|bubble|>`，模型仍可能只返回换行段落；发送层无法判断这些段落是闲聊气泡还是专业正文，因此会作为一条消息发送。缺少原始回复日志也使实际模型输出难以确认。

本次改动把角色设定与严格回复协议分别保存为独立 Markdown 文件，并在控制台输出每次模型进入微信整形前的原始最终回复。气泡边界仍由模型明确输出，不增加程序侧启发式切分。

## Goals

- 让微信角色设定集中在单独的 Markdown 文件中维护。
- 让微信回复格式、气泡协议和示例集中在另一个 Markdown 文件中维护。
- 强化闲聊必须输出 `<|bubble|>` 的约束，并保持专业回答不使用该标记。
- 让每次模型的原始最终回复在控制台清晰可见，便于确认分隔标记和换行。
- 保留现有好友隔离、消息发送、取消、工具和安全边界。

## Functional Requirements

- F1：微信角色设定必须始终从独立的 `role.md` 加载，不得再由微信配置中的 `system_prompt` 决定。
- F2：现有配置中残留的 `system_prompt` 不得覆盖或改变 `role.md`；使用说明不得继续引导用户配置该字段。
- F3：微信回复协议必须从独立的 `reply_policy.md` 加载，程序代码中不得继续保留同一份大段硬编码协议。
- F4：回复协议必须严格要求：可自然拆分的日常闲聊使用 `<|bubble|>` 作为唯一气泡边界；换行、空行和普通标点不能代替该标记。
- F5：回复协议必须明确要求：多个完整句子、问题或独立语义点不得挤在同一闲聊气泡中；简短单一语义回应允许只有一个气泡。
- F6：回复协议必须继续要求：专业知识、步骤、代码、资料和工具结果使用完整纯文本，不输出 `<|bubble|>`。
- F7：每次模型完成一条微信最终回复后，系统必须在清洗、来源处理、Markdown 移除和气泡切分之前，将原始最终回复输出到启动程序的控制台。
- F8：原始回复日志必须保留 `<|bubble|>`、换行和其他原始字符，使模型协议执行情况可直接观察。
- F9：原始回复日志必须具有稳定、可搜索的标签；不得同时输出系统提示词、API 密钥、工具参数、调用栈或内部会话档案。
- F10：模型取消、超时或失败且没有形成最终回复时，不得伪造原始回复日志。
- F11：缺少、为空或无法读取任何一个必需提示词文件时，机器人必须在启动或首次使用前明确失败，不得静默退回旧硬编码提示词。
- F12：气泡发送层仍只依据显式 `<|bubble|>` 切分；未输出该标记的文本保持现有专业正文路径，不增加按换行、标点或长度猜测闲聊的逻辑。

## Non-Functional Requirements

- N1：提示词文件在进程内只需加载一次，不得为每条好友消息重复读取磁盘。
- N2：不新增第三方依赖、模型调用或配置路径。
- N3：现有微信双版本 UIA、好友白名单、会话隔离、去重、目标复核、全局 FIFO、自然取消和只读工具边界保持不变。
- N4：控制台日志会包含好友对话内容；这是本次明确要求的本地可观测行为，不得额外写入新的日志文件或远端服务。
- N5：角色设定不得削弱回复协议、安全约束和工具权限边界。

## Out of Scope

- 根据换行、标点或语义启发式自动补切气泡。
- 增加第二次模型调用来判断闲聊或修复格式。
- 为不同好友配置不同角色或回复协议。
- 在运行时热更新提示词文件。
- 记录流式 token、模型内部推理、工具原始内容或系统提示词。
- 修改微信 UIA 控件选择器和消息发送方式。

## Acceptance Criteria

- AC1：启动微信运行时后，系统实际使用的角色文本与 `role.md` 内容一致；配置中的 `system_prompt` 即使存在也不会出现在模型系统提示词中。
- AC2：系统实际使用的回复协议与 `reply_policy.md` 内容一致，且包含唯一分隔标记、严格闲聊拆分规则、专业回答规则和代表性示例。
- AC3：模型返回 `第一条<|bubble|>第二条` 时，控制台先完整显示带分隔标记的原始文本，好友最终收到两条消息且看不到分隔标记。
- AC4：模型返回包含空行但没有 `<|bubble|>` 的文本时，控制台保留原始换行，发送行为保持为现有专业正文路径，不自动切成闲聊气泡。
- AC5：原始回复控制台输出具有固定标签，并发生在任何清洗与回复整形之前。
- AC6：取消、超时或模型错误路径不输出虚假的成功回复内容，现有受控错误行为不变。
- AC7：任一必需提示词文件缺失或为空时给出明确错误，且不存在硬编码协议回退。
- AC8：README 不再展示或说明 `wechat.system_prompt`，并说明角色与回复协议由两个 Markdown 文件提供。
- AC9：现有微信运行时、机器人、配置、安全和 UIA 回归测试继续通过。
