# Slash 命令注册与分发系统 Spec

## 背景

MewCode 当前在用户提交输入时直接判断少量固定字符串，以支持退出、会话恢复、上下文压缩和计划模式切换。现有方式没有统一的命令目录、别名校验、参数规则、帮助信息或补全能力；新增命令需要继续扩展输入入口，也容易让本应在本地完成的操作误入 Agent，造成额外等待、Token 消耗和不确定行为。

本章建立统一的 Slash 命令注册与分发能力。所有以 `/` 开头的输入优先由本地命令系统处理，只有普通输入与提示词类命令才进入对话。既有 `/exit`、`/resume`、`/compact`、`/plan`、`/do` 行为保持兼容，并新增帮助、状态、记忆、权限、会话、清理和代码审查命令。

## 目标

- 用统一命令目录管理名称、别名、说明、用法、类型、参数提示、可见性与执行行为。
- 在启动阶段发现全部名称或别名冲突并立即终止启动，避免运行期出现歧义。
- 将 Slash 命令与普通对话输入明确分流，使本地操作不经过 Agent、不消耗对话 Token。
- 提供大小写不敏感的解析、确定的参数校验、帮助信息和 Tab 补全。
- 让命令行为通过稳定的界面控制能力执行，不依赖具体 TUI 渲染实现。
- 保持现有权限模式、会话恢复、上下文压缩、流式 Agent 和档案语义不退化。

## 功能需求

- **F1: 命令目录与启动校验**
  每条命令登记规范名称、零个或多个别名、一句描述、用法、命令类型、可选参数提示、是否隐藏以及执行行为。规范名称与别名均按大小写不敏感方式参与唯一性检查；名称之间、别名之间、名称与别名之间发生任何冲突时，应用必须在进入交互界面前终止启动并给出可诊断错误。当前内置命令共十二个，全部公开。仅 `/help` 具有别名 `/h`，仅 `/clear` 具有别名 `/c`，其余内置命令暂无别名。

- **F2: 输入解析与分流**
  空输入直接忽略。非 `/` 开头的输入沿用普通用户消息流程。`/` 开头的输入必须绕过 Agent，由命令系统解析和分发，不得因未知命令而作为普通消息发送给模型。第一个空格前的内容为命令名，后续内容为参数；命令名统一按小写匹配，因此大小写不敏感。未知命令输出明确错误，并引导用户执行 `/help`。

- **F3: 命令类型与界面控制边界**
  命令分为纯本地、影响界面和提示词三类。纯本地命令只读取当前应用状态并显示结果；影响界面命令可以切换模式、管理会话、压缩上下文或退出；提示词命令将固定消息加入当前对话并立即触发 Agent 回合。命令执行只依赖通用的消息显示、用户消息发送、模式切换、Token 与回合统计、工具与记忆查询、状态刷新、会话管理和退出能力，不依赖具体渲染框架。

- **F4: 参数规则**
  `/help <命令名>` 是当前唯一接受参数的内置命令，且只接受一个命令名称或别名。其余命令收到任何非空参数时均拒绝执行，并显示该命令的用法。帮助查询参数可以使用规范名称或别名；未找到时按未知命令处理并引导 `/help`。

- **F5: 帮助与命令可见性**
  无参数 `/help` 按规范名称的字典序输出全部公开命令，每项显示“名字 + 一句描述”，形成两列对齐列表；别名不作为独立行重复展示。`/help <命令名>` 输出该命令的规范名称、别名、类型、描述、用法和参数提示。隐藏命令不出现在总帮助或补全候选中，但当前十二个内置命令均不隐藏。

- **F6: 输入框下方的实时命令菜单**
  当输入框内容变为 `/` 时，立即在输入框下方展开全部 `hidden=false` 的公开命令，无需按 Tab。继续输入命令前缀时，菜单按当前前缀实时过滤；规范名称和别名都参与匹配，同一命令只显示一次，候选按规范名称稳定排序。隐藏命令永不出现在菜单中。输入包含命令参数、前缀无匹配、用户按 Esc 或输入不再以 `/` 开头时，菜单关闭。

  菜单展开期间输入焦点始终保留在文本框。用户用上/下方向键移动高亮项，用 Tab、Enter 或鼠标点击选择；选择只把高亮项的规范名称写回输入框并关闭菜单，不立即执行命令。选择后再次按 Enter 才按正常提交路径执行。直接输入完整别名 `/h` 或 `/c` 并提交时，也必须执行对应命令。

- **F7: 十二个内置命令**

  | 命令 | 类型 | 行为 |
  |---|---|---|
  | `/exit` | 影响界面 | 关闭 TUI 进程。 |
  | `/plan` | 影响界面 | 将运行时权限模式切换到计划模式，不触发 Agent 回合。 |
  | `/do` | 提示词 | 先将运行时权限模式切回默认模式，再把既有执行指令作为用户消息加入对话并立即触发 Agent 回合；外部行为与本章实施前一致。 |
  | `/compact` | 影响界面 | 手动触发当前会话的上下文压缩，沿用既有压缩约束和无会话提示。 |
  | `/resume` | 影响界面 | 打开历史会话列表；选择后完整重放用户可见档案，并从最新有效压缩检查点重建模型上下文，沿用 Chapter 08 的全部会话恢复约束。 |
  | `/clear` | 影响界面 | 关闭当前会话档案，立即创建并打开一个新会话档案，清空内存消息、可见时间线、会话累计 Token 与会话回合数；随后只显示“已结束当前会话并开启新会话”的 notice。 |
  | `/help` | 纯本地 | 显示命令总表或单条命令详情。 |
  | `/status` | 纯本地 | 输出当前权限模式、当前会话累计输入/输出 Token、当前模式可用工具数量、已加载记忆条目数、当前模型名和当前工作目录。 |
  | `/memory` | 纯本地 | 分别列出当前加载的项目层与用户层记忆索引所引用的笔记文件名，只显示文件名，不展开正文。 |
  | `/permission` | 纯本地 | 输出当前权限模式的字符串名称，格式与 `/status` 完全一致。 |
  | `/session` | 纯本地 | 输出当前会话的 session 标识和档案文件路径；尚未创建会话时显示“当前尚未创建会话”，且不得因此创建档案。 |
  | `/review` | 提示词 | 将固定消息“请审查当前工作区中的代码变更，重点关注正确性、安全性、回归风险和测试缺口，并按严重程度报告问题。”作为用户消息加入对话并立即触发 Agent 回合；命令本身不读取 Git diff，也不预先收集外部上下文。 |

- **F8: 状态、工具和记忆口径**
  权限模式使用现有稳定字符串形式，包括 `default`、`acceptEdits`、`plan` 和 `bypassPermissions`。状态栏使用显式方括号模式标记，至少保证默认模式显示 `[DEFAULT]`、计划模式显示 `[PLAN]`，其他既有模式使用对应的大写标记；模式切换后立即刷新。`/status` 的可用工具数量等于当前权限模式下一次请求实际会暴露给模型的工具数量：计划模式只统计只读工具，其余模式统计全部已注册的内置与 MCP 工具。已加载记忆条目数等于项目层和用户层记忆索引当前引用的笔记条目合计数。`/memory` 使用相同索引口径，排除索引文件本身；索引缺失或没有条目时显示空状态和零条目。

- **F9: 会话 Token 与回合统计持久化**
  每次模型请求返回 Token usage 时，将输入与输出 Token 增量追加到当前会话 JSONL，并更新当前会话累计值；累计值持续显示在 TUI 状态栏，并由 `/status` 输出。每次普通用户消息、`/do` 或 `/review` 成功启动一次 Agent Loop 时，会话回合数增加一；同一 Agent Loop 内因工具调用产生的模型续轮不重复增加。回合统计同样写入会话档案。`/resume` 必须从档案恢复累计输入/输出 Token 与回合数；`/clear` 创建的新会话从零开始。

- **F10: 命令输出与档案边界**
  用户输入的命令文本本身不得作为用户消息写入对话或档案。纯本地命令的输出只显示在当前 TUI，不写入 JSONL，也不得为无会话状态创建会话。影响界面命令不作为模型消息；只有其既有业务需要持久化时才写入相应档案事件，例如压缩检查点和 `/clear` 新会话 notice。提示词命令注入的固定消息按普通用户消息处理，写入对话与 JSONL，并触发标题、上下文、Token 和回合统计等正常流程。

- **F11: 兼容提交入口**
  用户回车提交时必须先执行命令分流：命令由本地分发器处理，普通输入才进入 Agent。命令执行期间继续遵守现有空闲、流式、审批、压缩和恢复状态限制，不得绕过输入锁定或并发启动第二个 Agent 回合。

## 非功能需求

- **N1: 确定性与低延迟**
  纯本地命令不得调用模型或工具，结果只由当前本地状态决定，并应在正常交互延迟内完成。
- **N2: 启动安全**
  命令冲突必须在启动阶段失败，不允许以注册顺序覆盖、静默忽略或延迟到首次调用时才报错。
- **N3: 框架解耦**
  命令目录、解析、分发和内置命令行为应可在不启动真实 TUI 的情况下验证；更换界面渲染框架不应要求重写命令规则。
- **N4: 兼容性**
  既有 `/exit`、`/resume`、`/compact`、`/plan`、`/do` 外部行为，以及普通对话、MCP、权限、计划模式、流式输出、取消、会话恢复和上下文管理不得退化。
- **N5: 可用性**
  命令错误、参数错误、空记忆、无会话和补全无匹配均以用户可理解的信息处理，不抛出未捕获异常或让输入框失去焦点。内联菜单不得遮断输入编辑、状态栏或运行中输出，并应随终端尺寸变化保持在输入框下方可用。
- **N6: 隐私与上下文隔离**
  状态和帮助输出不得包含 API Key、记忆正文、工具参数或其他敏感内容；纯本地命令不得污染模型上下文。
- **N7: 统计一致性**
  状态栏、`/status`、当前会话档案与 `/resume` 恢复后的 Token 累计值必须一致；同一 Agent 回合不得重复累计会话回合数。

## 不做的事

- 用户自定义命令、项目级命令配置或运行时动态注册命令。
- 从 Skill 自动生成命令，或由模型动态生成提示词。
- 命令级权限控制、命令 allow/deny 规则或命令审批。
- `/review` 自动读取 Git diff、扫描文件或预先调用任何工具。
- 为当前十二个命令增加除 `/help <命令名>` 之外的业务参数或子命令。
- 在本章修复 Chapter 08 已记录的压缩检查点坐标系、摘要工具结果或手动压缩余量技术债；本章只保证 `/compact` 与 `/resume` 继续沿用其既有行为和约束。

## 验收标准

- **AC1: 注册与冲突失败**：十二个公开内置命令及 `/h`、`/c` 被注册；构造名称重复、别名重复或名称与别名冲突的命令集合时，应用在进入 TUI 前以可诊断错误终止启动，不发生覆盖。
- **AC2: 解析与分流**：空输入无动作；普通文本进入 Agent；命令名大小写不敏感；第一个空格后的文本作为参数；未知 `/...` 输入不进入 Agent，并显示未知命令与 `/help` 引导。
- **AC3: 参数规则**：`/help clear` 与 `/help c` 显示同一命令详情；不存在的帮助目标给出引导；其余十一条命令带参数时均不执行原行为并显示用法。
- **AC4: 帮助输出**：`/help` 仅列十二个规范名称，按字典序形成名字与描述两列；`/help <命令>` 展示名称、别名、类型、描述、用法和参数提示；全部内置命令均公开可见。
- **AC5: 内联补全体验**：输入框内容刚变为 `/` 时，无需 Tab 即在输入框下方显示全部十二个公开规范命令；继续输入后按规范名称或别名前缀实时过滤，候选按规范名称排序且不重复，隐藏命令不显示。菜单展开时焦点留在输入框，上/下键移动高亮，Tab、Enter 或点击只填入规范名称并关闭菜单，第二次 Enter 才执行；Esc、出现参数、无匹配或离开 Slash 输入时关闭菜单。`/h`、`/c` 仍可直接调用。
- **AC6: 既有命令兼容**：`/exit` 正常退出；`/plan` 进入计划模式并将状态栏标记刷新为 `[PLAN]`；`/do` 回到默认模式、将状态栏标记刷新为 `[DEFAULT]`、注入既有执行指令并启动一个回合；`/compact` 触发手动压缩；`/resume` 完整重放可见历史并按 Chapter 08 最新有效检查点恢复模型上下文。
- **AC7: `/clear` 新会话**：有无当前会话时执行 `/clear` 均得到一个新 session 标识和已打开的空 JSONL；旧档案被关闭且内容保留；内存消息、时间线、累计输入/输出 Token 与回合数归零；界面只剩指定 notice，notice 写入新档案。
- **AC8: 本地状态命令**：`/status` 准确显示六项规定信息；计划模式工具数只含只读工具，其他模式含全部内置与 MCP 工具；`/permission` 与 `/status` 使用相同模式字符串；`/session` 显示 ID 与路径，空会话时不创建档案；这些命令均不触发模型请求。
- **AC9: 记忆命令**：项目层与用户层索引引用的笔记文件名被分层列出且不显示正文，索引本身不计入；`/status` 记忆数量与 `/memory` 所列条目合计一致；缺失和空索引得到确定的空状态。
- **AC10: 提示词命令**：`/review` 只把批准的固定审查消息写入对话并立即启动一个回合，不在分发阶段读取 Git diff 或收集上下文；`/do` 与 `/review` 的命令原文不入档，注入消息按普通用户消息进入 JSONL。
- **AC11: Token 与回合恢复**：同一会话中每次模型请求的输入/输出 usage 增量写入 JSONL并同步更新状态栏；普通消息、`/do`、`/review` 各增加一个会话回合，工具续轮不增加；退出并 `/resume` 后累计 Token 与回合数恢复为退出前值。
- **AC12: 档案与上下文隔离**：`/help`、`/status`、`/memory`、`/permission`、`/session` 的输入和输出均不写入 JSONL、不创建会话、不进入模型上下文；影响界面命令只写其业务要求的事件。
- **AC13: 不退化**：命令域测试、TUI 路由与补全测试、会话统计恢复测试和至少一个完整端到端场景通过；全量测试、编译、静态检查与格式检查通过，既有 Agent、Provider、工具、MCP、权限、会话、上下文和记忆行为保持正常。
