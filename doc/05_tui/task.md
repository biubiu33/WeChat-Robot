# TUI 展示优化 Tasks

## 文件清单

| 操作 | 文件 | 职责 |
|---|---|---|
| 新建 | `src/mewcode/tui/timeline.py` | 可挂载条目的 `VerticalScroll` 时间线与条件自动滚动。 |
| 修改 | `src/mewcode/tui/view.py` | 用户、助手、工具、错误、通知和活动区的语义化条目工厂。 |
| 修改 | `src/mewcode/tui/app.py` | 主布局改用时间线，提供追加条目入口和 TUI CSS。 |
| 修改 | `src/mewcode/tui/stream.py` | 将现有 Agent 事件映射为时间线条目和活动区。 |
| 修改 | `tests/test_tui.py` | 展示语义、折叠结果、滚动、输入恢复与既有工作流回归。 |

## T1: 条件自动滚动时间线

**文件：** `src/mewcode/tui/timeline.py`

**依赖：** 无

**步骤：**
1. 新建继承 `VerticalScroll` 的 `Timeline`。
2. 提供 `is_near_bottom()`，以当前纵向滚动偏移、最大滚动偏移和小容差判断是否跟随最新内容。
3. 提供异步 `append(entry)`：挂载前记录底部状态，挂载后仅在原本接近底部时于刷新完成后无动画滚动到底部。
4. 不在用户阅读历史时调用滚动 API；不保存或修改会话数据。

**验证：** 在 Textual 测试中追加足够多条目，断言底部追加会跟随、手动滚到顶部后追加不改变读取位置。

## T2: 语义条目与可折叠工具结果

**文件：** `src/mewcode/tui/view.py`

**依赖：** T1

**步骤：**
1. 将用户、助手、错误和通知渲染改为返回可挂载的独立 Widget，并附加语义 class。
2. 用户条目包含稳定的用户标题、完整问题文本和高亮背景样式标识。
3. 工具结果使用 `Collapsible`，默认收起；标题显示工具名、成功/失败状态和 `_argument_preview()` 提供的安全摘要。
4. 工具展开区沿用既有摘要截断逻辑，保留成功/错误样式；不在标题或正文中额外引入 `write_file.content` 等敏感参数。
5. 保留状态栏、Provider 选择和参数安全预览的既有语义；将活动区的英文状态文本替换为中文。

**验证：** 单元测试断言用户、助手、错误、通知和工具条目 class 不同；`Collapsible.collapsed` 初始为真；写文件 `content` 不出现在标题。

## T3: 固定布局与时间线追加入口

**文件：** `src/mewcode/tui/app.py`

**依赖：** T1、T2

**步骤：**
1. 用 `Timeline(id="timeline")` 替换主区 `RichLog`，使其成为唯一占据 `1fr` 高度的区域。
2. 保留流式活动区、输入框和状态栏在时间线之后的垂直顺序，保证输入区固定在底部。
3. 新增异步 `append_timeline(entry)`，统一调用 `Timeline.append()`。
4. 将启动横幅、`/plan` 通知和用户提交消息改为通过该入口写入时间线。
5. 调整 CSS：用户高亮、助手、工具成功/错误、通知与错误使用克制的语义样式；输入框占位文本改为中文；移除已废弃的 `#log` 样式。
6. 保持 Provider 选择、状态栏、输入锁定、焦点恢复和命令处理逻辑不变。

**验证：** 使用 `run_test()` 断言 `#timeline` 存在、`#input` 与 `#statusbar` 在主区底部；提交用户消息后出现高亮用户条目。

## T4: 流式事件映射到时间线

**文件：** `src/mewcode/tui/stream.py`

**依赖：** T2、T3

**步骤：**
1. 移除 `RichLog` 查询和直接写入；全部最终条目改为 `await app.append_timeline(...)`。
2. 新建仅供展示的 `ToolRun` 记录，替代运行中工具的元组列表，维持 Agent 事件顺序的入队/出队。
3. 工具开始时提交已有助手文本、登记执行中工具并刷新活动区；工具结束时追加默认折叠的工具结果条目。
4. 正常助手回复、错误、通知与取消分别追加对应语义条目；结果和会话写入顺序保持当前行为。
5. 流式活动区只更新临时 `#streaming`，不向时间线逐 token 追加条目或强制滚动；回合结束后清空活动区并恢复输入焦点。
6. 不修改 `Agent` 创建、事件消费顺序、token 累计、取消事件、工具执行或会话对象。

**验证：** 运行现有普通对话、工具调用、取消和错误 TUI 测试；断言最终条目顺序与原行为一致，活动区在结束后为空。

## T5: TUI 展示与交互测试

**文件：** `tests/test_tui.py`

**依赖：** T1-T4

**步骤：**
1. 更新 Fake Provider 与辅助断言，适配 `Timeline` 而非 `RichLog`。
2. 覆盖用户高亮条目、助手/错误/通知语义 class 和中文活动状态。
3. 覆盖工具结果默认收起、安全标题、展开后的摘要内容和错误样式。
4. 覆盖时间线条件自动滚动：底部跟随、历史位置不跳转、返回底部后恢复跟随。
5. 保留并运行多轮输入、计划/执行切换、Esc 取消、错误恢复、token 状态栏及输入焦点测试。
6. 增加窄尺寸 `run_test(size=...)` 断言，确保输入区和状态栏仍存在且不被时间线挤出。

**验证：** `python -m pytest tests/test_tui.py -q` 通过。
