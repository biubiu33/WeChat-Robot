# MewCode 交互式对话 TUI 规格

## 背景
MewCode 是一个从零开始开发的 Python 命令行 AI 助手。本阶段目标是先完成一个纯对话能力：用户在终端启动 MewCode 后进入交互式对话界面，可以输入中文或其他文本问题，MewCode 调用大模型 API，并把回复以流式方式逐步打印到终端。

本阶段只做会话体验和 LLM Provider 抽象，不实现工具调用、文件操作、代码编辑或其他 agent 行为。当前工作区没有已有实现，因此本规格定义初始项目行为。

## 目标
- 提供一个命令行交互式对话界面。
- 支持中文输入、中文提示和中文输出。
- 使用 UTF-8 写入项目文本文件、配置文件和文档。
- 使用 YAML 配置文件管理多个 LLM 供应商配置。
- 启动时允许用户通过配置名称选择当前使用的 LLM 供应商配置。
- 支持 Anthropic Claude 兼容协议和 OpenAI 兼容协议。
- 响应必须以流式方式逐步输出，而不是等待完整回复后一次性输出。
- 在同一次运行会话中保留多轮对话历史，使后续问题可以引用之前内容。
- 支持在 Claude 兼容配置中启用 extended thinking。
- 将不同供应商的差异封装在统一 Provider 抽象之后，方便后续扩展新后端。

## 功能需求
- F1：用户可以从命令行启动 MewCode，并进入交互式终端对话界面。
- F2：终端界面可以反复接收用户文本输入，直到用户退出会话。
- F3：终端界面的提示、错误信息和普通状态信息使用中文输出。
- F4：终端界面可以正确接收中文输入，并在发送给 LLM 后保留中文内容。
- F5：每次用户发送消息时，MewCode 会把当前会话上下文发送给所选 LLM 后端。
- F6：助手回复必须随着后端流式事件到达而逐步打印到终端。
- F7：同一次会话中，MewCode 会记住之前的用户消息和助手消息。
- F8：MewCode 从 YAML 配置文件读取 LLM 供应商配置。
- F9：每个供应商配置包含六个字段：`name`、`protocol`、`model`、`base_url`、`api_key`，以及可选的 `thinking`。
- F10：YAML 配置文件可以包含多个供应商配置。
- F11：用户可以在启动时通过 `name` 选择供应商配置，例如 `mewcode --profile claude`。
- F12：MewCode 支持 Anthropic Claude 兼容的流式协议。
- F13：MewCode 支持 OpenAI 兼容的流式协议。
- F14：当 Claude 兼容配置启用 `thinking` 时，MewCode 会向后端请求 extended thinking。
- F15：交互式对话界面不需要理解供应商协议差异，这些差异由 Provider 层处理。
- F16：当配置缺失、配置格式无效或指定配置名称不存在时，MewCode 会输出清晰中文错误，并且不会进入不可用的对话会话。
- F17：当 API 请求失败或流式响应中断时，MewCode 会输出清晰中文错误，并允许用户继续输入或退出。

## 非功能需求
- N1：本阶段不实现工具调用、文件操作、代码编辑、Shell 执行或任何 agent 动作。
- N2：只要后端开始返回流式响应事件，终端就应尽快显示可见输出。
- N3：API Key 不得出现在正常日志、错误信息或终端输出中。
- N4：Provider 抽象应允许后续增加新的 LLM 后端，而不需要重写终端对话主流程。
- N5：项目应作为本地 Python 包运行和测试。
- N6：第一阶段的终端界面保持简单、稳定、可预测。
- N7：项目创建或修改的文本文件应使用 UTF-8 编码。

## 范围外
- 工具调用或函数调用。
- 作为 agent 读取、写入、搜索或编辑项目文件。
- 代表用户运行 Shell 命令。
- 跨 MewCode 启动保存历史会话。
- 复杂 TUI 布局或全屏终端 UI。
- 模型自动选择或供应商自动检测。
- API Key 以外的认证方式。
- 非流式回复模式。

## 验收标准
- AC1：给定包含多个配置的有效 YAML 文件，使用已存在的配置名称启动 MewCode 时，会使用该配置进入聊天会话。
- AC2：给定包含多个配置的 YAML 文件，使用不存在的配置名称启动 MewCode 时，会显示清晰中文错误，并且不会进入聊天循环。
- AC3：给定有效的 OpenAI 兼容配置，用户发送消息后，MewCode 会使用流式请求并逐步打印助手文本。
- AC4：给定有效的 Claude 兼容配置，用户发送消息后，MewCode 会使用流式请求并逐步打印助手文本。
- AC5：给定启用 `thinking` 的 Claude 兼容配置，MewCode 会向后端请求 extended thinking。
- AC6：在同一次会话中，后续用户消息可以依赖之前的对话内容，因为先前轮次会被包含在请求上下文中。
- AC7：用户输入退出命令或发送输入结束信号时，聊天会话可以干净退出。
- AC8：YAML 配置中的 API Key 不会出现在用户可见输出中。
- AC9：本阶段不提供工具调用、文件操作、代码编辑或 Shell 执行能力。
- AC10：用户输入中文问题时，MewCode 能正确接收并发送；助手返回中文内容时，终端能正确逐步显示。
- AC11：项目文本文件、示例配置和规格文档以 UTF-8 编码保存。
