# Skill 系统规格

## 背景

当前 MewCode 要求用户在每次对话中重复描述可复用的 AI 工作流。应用需要一套本地
Skill 系统：将工作流及其辅助文件封装为能力包，使 Agent 能发现可用 Skill 的名称和用途，
但不在启动时加载完整指令，并允许用户直接调用这些能力。

## 目标

- 让用户可以用可移植的 Markdown Skill 定义可复用的 AI 工作流。
- 让 Agent 先发现可用 Skill 的名称和用途，仅在实际需要时加载完整指令。
- 同时支持共享主对话和隔离执行，并保持清晰的历史边界。
- 通过收窄每个 Skill 的可用工具，提高工具选择准确性。
- 提供 `commit`、`review`、`test` 三个内置样板 Skill。

## 功能需求

- F1：Skill 可以是单个 Markdown 文件，也可以是目录型能力包。目录型 Skill 的入口
  Markdown 文件可配套模板、示例、脚本和参考文档，并作为一个完整 Skill 被发现和分发。
- F2：每个 Skill 入口由 YAML frontmatter 和 Markdown 正文构成。frontmatter 声明唯一
  名称、一句话说明、可见工具白名单、执行模式、独立执行的历史设置和可选指定模型；
  正文是发送给模型的 SOP 指令。
- F3：Skill 指令支持参数占位符。调用 Skill 时，斜杠命令或加载工具传入的参数会替换
  占位符，且不会暴露无关的主对话历史。
- F4：系统从项目级、用户级和内置位置发现 Skill，优先级依次降低。高优先级位置的同名
  Skill 覆盖低优先级定义。单个文件解析失败时应输出诊断信息并跳过，不能阻断其他 Skill
  的加载。
- F5：应用启动时，Agent 只接收每个生效 Skill 的名称和一句话说明；在请求系统级加载
  工具之前，不接收其 SOP 正文。
- F6：系统级加载工具校验指定 Skill、激活它、渲染参数占位符，并将完整指令返回给
  Agent。即使激活 Skill 声明了工具白名单，该工具仍始终可用。
- F7：每轮 Agent 请求的环境上下文最显眼位置都必须包含所有已激活 Skill 的完整指令。
  多个 Skill 可以同时保持激活，直至清空对话或应用会话结束。
- F8：`inline` Skill 在当前对话中执行，执行过程和结果保留在主可见历史中，并遵循主对话
  的正常生命周期。
- F9：`fork` Skill 在隔离的 Agent 对话中执行。不传递任何主对话历史，仅将调用该 Skill
  时传入的参数作为用户输入；执行完成后仅向主对话回流结果摘要，不导入隔离对话的工具调用
  或完整记录。
- F10：激活 Skill 后，其工具白名单会收窄模型可见的普通工具。启动时，如果任一 Skill
  声明了不存在的普通工具，应用必须立即以可诊断错误终止启动。系统级 Skill 加载和安装工具
  不受白名单约束。
- F11：每个已发现的生效 Skill 都自动注册为 `/<name>` 斜杠命令。调用命令会加载 Skill
  并进入其声明的执行模式；Skill 位置内容变动后，命令发现结果无需重启应用即可刷新。
- F12：`/skill` 命令列出当前生效及已激活的 Skill，但不得展示完整 SOP 正文。清空对话时
  同时清空所有已激活 Skill。
- F13：系统级安装工具支持 HTTPS URL 或本地 ZIP 包，将合法第三方 Skill 安装到用户级位置；
  它必须拒绝明文 HTTP 来源，并阻止压缩包条目逃逸安装目录。
- F14：MewCode 内置的 `commit`、`review`、`test` 样板 Skill 与用户提供的 Skill 使用
  完全一致的发现、加载、执行和工具白名单规则。

## 非功能需求

- N1：Skill 解析、优先级、工具校验、激活、命令注册和执行模式路由可以在没有真实 TUI 或
  Provider 的情况下测试。
- N2：未被选择的无效 Skill 文件不能使其他有效 Skill 不可用；已选择 Skill 在运行时失败时，
  应显示用户可理解的错误，且不得破坏主对话。
- N3：隔离执行的内部消息、工具输入和工具输出不得污染主对话归档。
- N4：工具白名单必须与既有权限模式安全组合，不能授予原本被拒绝的权限。
- N5：Skill 安装不得写入指定用户级安装位置之外的文件，且安装过程中不得执行能力包脚本。

## 不做的事

- Skill 市场、远程浏览、发布、评分或分享界面。
- Skill 版本管理、依赖解析、升级或回滚。
- 明文 HTTP 安装来源。
- 向 `fork` Skill 传递任何主对话历史。
- 在应用重启或会话恢复后持久化已激活 Skill 状态。

## 验收标准

- AC1：包含完整元信息的有效单文件和目录型 Skill 均可被发现；启动提示词中不存在其 SOP
  正文。
- AC2：项目级、用户级和内置 Skill 的优先级确定；同名 Skill 中仅最高优先级定义可被列出、
  加载和调用。
- AC3：格式错误的 Skill 会被跳过并产生诊断，而其他有效 Skill 仍可使用；工具白名单含有
  不存在的普通工具时，启动失败且错误指出对应 Skill。
- AC4：加载工具可按需加载指定 Skill、替换传入参数，并使其完整指令在清空前的每次后续
  Agent 请求中可见。
- AC5：多个已激活 Skill 在每次重建的请求上下文中同时存在，`/clear` 后全部移除。
- AC6：`inline` Skill 在主对话中运行，且其结果保留在主可见历史和持久化历史中。
- AC7：`fork` Skill 只接收调用参数，在隔离对话中运行，并且只向主对话返回完成摘要。
- AC8：已激活 Skill 只暴露其声明的普通工具和系统级 Skill 工具；既有权限模式和计划模式
  限制继续生效。
- AC9：每个生效 Skill 都有可用的 `/<name>` 命令；Skill 位置改变后，命令列表无需重启
  应用即可更新。
- AC10：`/skill` 能展示生效及激活状态，但不输出完整 SOP 指令。
- AC11：安装工具接受 HTTPS 和本地 ZIP 来源、拒绝 HTTP、阻止路径穿越，并使安装成功的能力包
  出现在用户级 Skill 位置。
- AC12：内置 `commit`、`review`、`test` Skill 可被发现，并可通过与其他 Skill 相同的接口使用。
- AC13：完整验证套件继续覆盖既有 Agent、工具、MCP、权限、命令、会话、上下文和记忆行为。
