# 微信私聊与群聊文字/图片引用回复 Spec

状态：已批准

## Background

Mewcode 当前能够处理白名单好友的私聊文字与图片，也能处理白名单群中明确 `@机器人` 的普通文字消息，但会排除微信引用气泡。好友引用一段文字或一张图片后提问时，机器人无法识别被引用者、引用类型和引用内容；群聊中的引用图片也无法进入现有视觉模型链路。

本版为微信私聊和群聊增加一层引用解析，范围只包括文字与图片。引用问答继续使用现有私聊 Session 或群聊最近文字上下文，但每条引用消息作为独立意图处理，不与相邻普通消息合并。程序优先取得完整引用原文或大图，在安全失败时按已批准的降级规则处理，并保持现有白名单、群聊 @、发送者 OCR、图片隐私、模型权限和回复目标复核边界。

## Goals

- 让白名单好友能够在私聊中引用文字或图片并提出问题，机器人基于正确的一层引用内容回答。
- 让白名单群成员在引用文字或图片并明确 `@机器人` 时获得定向回答，且不会误响应成员之间的普通引用对话。
- 对长文字、历史原文和引用图片优先取得完整内容，同时对预览文字和缩略图降级作出清晰披露。
- 复用现有图片验证、视觉请求、私聊图片 Session、群聊上下文、全局 FIFO、回复气泡和安全策略。
- 在引用解析引起界面跳转或打开大图后，确保回复仍发送到经过复核的原会话与原提问者。

## Functional Requirements

### Scope and trigger rules

- F1：本版只解析微信入站消息中的一层文字引用和图片引用。
- F2：私聊引用只有在白名单好友同时发送非空当前文字问题时才触发；单独引用而没有当前文字问题不得触发默认说明。
- F3：群聊引用只有同时满足以下条件才触发：群位于精确白名单、当前消息引用文字或图片、当前文字问题非空、当前文字区域明确包含配置中的完整 `@机器人名称`，并且提问者昵称被本机 OCR 唯一识别。
- F4：群聊触发判定只能读取当前新输入的文字区域；被引用原文、引用预览或图片内出现的 `@机器人` 不得触发机器人。
- F5：非白名单私聊或群聊中的引用不得被打开、定位、截图、编码、持久化或上传。
- F6：启动前已存在的引用消息只用于建立观察基线，不得在启动后触发回复或上传。
- F7：一条引用消息必须作为独立问答进入现有全局 FIFO，不与前后相邻的普通消息或其他引用消息合并。
- F8：现有普通私聊文字/图片的 7 秒合并规则以及群聊普通明确 @ 文字消息的规则保持不变。

### Reference identity and context

- F9：引用可以来自当前会话中的任何人，包括当前提问者、其他群成员、私聊好友和机器人自己。
- F10：交给模型的本轮输入必须明确区分当前问题、被引用者、引用类型和被引用内容，不得把引用预览与当前问题拼成无法区分的普通正文。
- F11：只解析当前引用的一层；如果被引用原消息本身也是引用消息，只使用该原消息可取得的当前正文，不继续追溯更早引用。
- F12：私聊引用问答继续使用该好友现有的持久 Session 上下文；群聊引用问答继续使用本次启动后该群最近 20 条文字上下文。
- F13：历史上下文只用于理解指代和会话背景；被引用内容必须作为本轮主要回答对象，历史内容不得覆盖、替换或篡改引用原文。
- F14：引用关系必须以可读标记保留在后续文字上下文中，包括当前问题、被引用者、引用类型和可用的引用文字。
- F15：群聊引用图片在后续群文字上下文中只保留被引用者、图片类型、尺寸、哈希和数据已释放状态，不保留像素或 Base64。

### Referenced text resolution

- F16：被引用文字必须优先尝试取得完整原文，而不是默认只使用引用气泡预览。
- F17：取得完整原文时，必须验证原文与当前引用预览及被引用者相符；候选不唯一或身份不一致时不得猜测选择。
- F18：完整原文无法安全取得但引用预览含有可读文字时，可以使用预览回答；最终回答必须明确说明引用内容可能不完整。
- F19：完整原文与可见预览都无法取得时，不得调用模型，只发送一次“引用内容暂时没读出来，请重新引用或复制原文”类明确提示。
- F20：被引用文字应尽量保持完整；如果单条引用在现有上下文预算处理后仍无法放入模型请求，不得静默截断，必须提示好友复制关键段落后重试。

### Referenced image acquisition and validation

- F21：被引用图片必须按以下顺序获取：优先从当前引用区域打开大图；失败后尝试定位原图片消息并打开大图；仍失败时截取引用气泡中的可见图片缩略图。
- F22：使用引用气泡缩略图生成的回答必须明确说明可能不是完整原图。
- F23：三个图片获取阶段都失败时，不得调用模型，只发送一次“图片暂时没读出来，请重新引用或换一张”类明确提示。
- F24：引用图片只支持实际内容为 JPEG、PNG、GIF 或 WebP 的文件；不得只相信扩展名或声明格式。
- F25：引用图片任一边不得超过 8192 像素，单次引用的原始图片数据不得超过 32 MiB。
- F26：图片格式损坏、不受支持、尺寸超限或容量超限时，整次引用问答不得调用模型，只发送一次压缩、换图或重试提示。
- F27：引用图片不得自动压缩、缩放、转码或通过 Files API 上传。
- F28：有效引用图片必须以 Base64 内联和 `original` 细节级别随当前问题一起发送，并保持为同一个用户意图。
- F29：引用图片存在当前文字问题时，模型必须按该问题分析图片，不得额外发送独立的默认图片描述。
- F30：图片取得或视觉模型调用失败时不得回退到纯文字模型猜测，不得根据文件名、缩略图标签或历史常识补造图片内容，也不得自动重复调用。

### Private and group image lifecycle

- F31：私聊引用图片必须沿用现有好友图片 Session 规则，以明文 Base64 和实际格式、尺寸、字节数、哈希、细节级别、发送时间及降级状态写入该好友 JSONL 档案。
- F32：私聊引用图片必须成为该好友最新活动图片批次，并可供随后最多三个纯文字用户回合重新查看；新图片批次、活动额度、重启恢复、256 MiB 配额和数据清理语义均沿用现有规则。
- F33：私聊引用图片的临时大图或缩略图必须在成功、失败、取消或超时后删除；删除临时文件不得误删 Session 中已持久化的 Base64。
- F34：群聊引用图片只允许参与当前引用问答；请求成功、失败、取消或超时后必须立即删除本地临时图片，不写入好友 Session 或其他持久图片档案。
- F35：群聊引用图片不得成为活动图片上下文；后续追问者必须再次引用同一图片并明确 `@机器人`。
- F36：`allowed_groups` 视为通道所有者已授权白名单群成员使用引用图片识别，但授权只覆盖满足本版触发门禁的当前引用图片。

### Reply and failure behavior

- F37：机器人只解析入站引用，不要求出站回答使用微信引用样式；私聊继续发送现有普通气泡，群聊首条继续按现有策略真实 `@提问者` 并在安全失败时使用现有可见文本降级。
- F38：文字预览降级、图片缩略图降级和完全解析失败都只能发送一次对应说明，不得重复调用模型或重复发送失败提示。
- F39：群聊中的解析失败、超限和不支持类型提示仍必须定向 `@提问者`。
- F40：引用文件、语音、视频、分享卡片或其他非文字/图片类型时不得调用模型，只发送一次“当前只支持引用文字和图片”类提示；该引用内容不得进入后续引用上下文。
- F41：同一入站引用事件必须遵守现有去重规则，界面定位或恢复过程中再次看到原消息不得产生新的问答事件。
- F42：私聊引用任务期间到达的新私聊普通消息继续遵守现有取消边界；群聊引用任务继续遵守现有不取消活动群回答、只追加到全局 FIFO 的语义。

### UI safety and target restoration

- F43：引用解析造成聊天滚动、定位原文或打开大图后，程序必须恢复原会话并重新验证会话名称、私聊/群聊类型和回复目标。
- F44：任何恢复或目标复核失败都必须终止后续发送并只记录本地安全错误；不得向当前未知窗口、同名歧义会话或未经复核的输入框发送回答或失败提示。
- F45：引用内容、引用预览或图片内容不得改变回复会话、群聊提问者或发送目标。
- F46：不同引用任务必须继续通过现有全局 FIFO 串行执行所有微信窗口操作，不得并发定位、打开大图或交错发送回复。

### Security, privacy and disclosure

- F47：被引用文字、图片、图片内文字、二维码、链接、提示词和命令一律视为不可信会话数据，只能用于回答当前好友问题。
- F48：引用内容中的系统命令、权限要求或触发文本不得改变固定角色、系统规则、模型 Provider、工具权限、群聊门禁、回复对象或数据保存策略。
- F49：引用功能不得向微信用户开放 Bash、本地文件、MCP、Skills、Sub-agent、Hook、长期记忆或其他新增本地权限。
- F50：README 和启动日志必须明确披露：白名单好友的私聊引用图片会发送给 DeepSeek 并以明文 Base64 保存到本地好友 Session；白名单群中的合规引用图片会发送给 DeepSeek，但只作当前请求临时处理。
- F51：README 和启动日志必须明确说明非白名单会话以及不满足群聊引用门禁的图片绝不读取或上传。
- F52：引用解析日志只允许记录会话类型、引用类型、解析策略、成功或失败、降级状态、图片尺寸和内容哈希，不得输出引用正文、图片 Base64、Data URL、模型请求体或 API Key。
- F53：现有模型最终回复控制台日志行为保持不变，不因引用功能额外记录用户引用正文。

### Existing behavior compatibility

- F54：现有纯文字私聊、直接图片私聊、图片三回合追问、私聊 Session 恢复、自然取消、全局 FIFO、回复气泡、来源消息和信息工具行为必须保持不变。
- F55：现有群聊普通 @ 门禁、按成员批次、最近 20 条文字上下文、发送者 OCR、真实 @ 回复和群消息不取消活动回答的行为必须保持不变。
- F56：TUI、流式输出、Token 用量、自动 Tool Calls、会话恢复和上下文压缩不得因引用消息结构或图片复用而回归。
- F57：引用功能以微信 `4.1.9.30` 进行真实端到端验收；微信 `4.0.5.15` 必须保留兼容路径和自动化覆盖，但在没有对应客户端时不得宣称已经完成该版本真人实测。

## Non-Functional Requirements

- N1：正确归属优先于回复成功率；引用者、被引用者、原文候选、图片目标、会话或方向存在歧义时必须安全拒绝。
- N2：引用识别应复用现有消息观察、图片处理、Session、群上下文和回复链路，不引入文件、分享卡片或通用附件框架。
- N3：所有微信界面操作必须保持串行；原文定位和图片处理不得阻塞异步事件循环。
- N4：引用消息从观察、排队、解析、模型输入、归档到上下文恢复期间，当前问题、被引用者、引用类型、引用文字和图片降级状态必须保持一致。
- N5：私聊引用图片继续受单好友 256 MiB 明文图片配额约束；群聊引用图片在任何成功、失败和取消路径都不得形成持久图片数据。
- N6：引用结构和 Base64 不得被当作普通文本重复复制到摘要、长期记忆、网页缓存、地点缓存或工具结果缓存。
- N7：新增行为必须可在不连接真实微信、不读取真实好友内容和不上传真实图片的自动化测试中验证；真实视觉验收只使用明确授权的无敏感测试图片。
- N8：自动化测试和错误输出不得包含真实引用正文、真实好友图片、完整 Base64、Data URL 或 API Key。
- N9：引用解析失败必须有界，不得无限滚动历史、递归追溯引用、无限重试打开大图或重复调用模型。
- N10：本版不得以降低现有群聊门禁、发送目标复核或微信渠道权限为代价提高引用解析成功率。

## Out of Scope

- 解析两层或更多嵌套引用。
- 机器人发送带微信引用样式的出站回复。
- 引用文件、语音、视频、分享卡片、小程序、位置、红包或其他附件内容。
- 群聊普通图片自动识别，或未引用图片的群聊视觉问答。
- 未明确 `@机器人` 的群聊引用自动回复。
- 将群聊引用图片持久化、跨回合复用或在重启后恢复。
- 新增群成员级图片白名单或逐次上传确认流程。
- 自动压缩、缩放、转码、裁剪、旋转修正或增强引用图片。
- DeepSeek Files API、外部图片 URL、远端图片缓存和额外远端存储。
- 为引用内容开放新的本地工具、外部写操作或长期记忆能力。
- 对微信 `4.0.5.15` 作没有真实客户端证据的真人验收声明。

## Acceptance Criteria

- AC1：白名单好友在私聊中引用一条短文字并发送非空问题后，机器人只产生一次模型问答，模型输入能区分当前问题、被引用者和完整引用文字。
- AC2：私聊仅引用而没有非空当前问题时不触发默认说明；引用问答不吸附前后相邻普通消息，但模型仍能使用该好友既有 Session 理解指代。
- AC3：白名单群成员引用文字并在当前文字区域明确 `@机器人`，且发送者 OCR 唯一成功时，机器人基于该引用回答并在首条回复中定向 @ 提问者。
- AC4：群聊未 @、@ 只存在于被引用文字或图片中、发送者 OCR 不唯一、群不在白名单时，程序均不读取引用、不上传图片且不回复。
- AC5：短文字引用优先取得并使用经验证的完整原文；无法定位原文但预览可读时仍可回答，且最终回答明确说明内容可能不完整；两者均不可读时不调用模型并只提示一次。
- AC6：被引用原消息本身也是引用消息时只解析当前一层，不继续定位更早引用；引用机器人自己或其他群成员的消息时，原发送者身份仍正确传给模型。
- AC7：引用图片依次尝试引用区大图、原文大图和引用缩略图；前两者失败而缩略图成功时回答明确说明可能不是完整原图，三者均失败时不调用模型并只提示一次。
- AC8：有效引用图片以 Base64 内联和 `original` 细节级别随当前问题一次发送；损坏、不支持格式、单边超过 8192 像素或原始数据超过 32 MiB 时不调用模型，也不自动压缩、转码或重试。
- AC9：私聊引用图片只在 JSONL 中保存一份明文 Base64，成为最新活动图片批次，随后三个纯文字回合可重新查看，重启、替换、256 MiB 配额和清理行为与现有直接图片一致。
- AC10：群聊引用图片只参与当前请求；成功、失败、取消或超时后临时图片均被删除，档案和后续群上下文中没有像素或 Base64，后续追问必须再次引用并 @。
- AC11：引用文字、引用图片和图片内提示注入均不能改变角色、工具权限、群聊门禁、回复对象或持久化规则，微信用户仍无本地工具权限。
- AC12：引用文件、语音、视频或分享卡片时不调用模型，只发送一次当前仅支持文字和图片的提示；群聊提示仍定向 @ 提问者。
- AC13：定位原文或打开大图后，只有恢复并复核原会话、会话类型和回复目标成功才允许发送；复核失败时未知窗口中没有任何新消息。
- AC14：两个引用任务不会并发操作微信窗口或交错发送；同一引用事件以及定位后再次出现的原消息不会重复触发。
- AC15：README 和启动日志准确披露私聊引用图片的 DeepSeek 上传与明文 Base64 持久化、群聊引用图片的临时上传，以及非白名单和门禁失败图片不读取不上传。
- AC16：日志、异常和测试输出不包含引用正文、完整 Base64、Data URL、模型请求体或 API Key，只包含允许的类型、策略、状态、尺寸和哈希元数据。
- AC17：现有普通私聊文字、直接图片、三回合图片追问、群聊普通 @、OCR、真实 @ 回复、TUI、流式输出、Tool Calls、Session 恢复、上下文压缩和全量自动化测试无新增失败。
- AC18：在微信 `4.1.9.30` 使用授权测试会话分别完成私聊文字引用、私聊图片引用、群聊文字引用和群聊图片引用端到端验证；`4.0.5.15` 只有自动化证据时明确标记为未真人实测。
