# 微信群聊 @ 触发与按成员批处理 Spec

状态：已批准

## Background

Mewcode 当前微信通道只扫描私聊，会把会话名直接当作发送者，并按好友名维护 7 秒静默窗口和持久化模型 Session。这个假设不适用于群聊：群名不是发送者名，不同成员会交叉发言，普通群消息也不一定是在对机器人说话。

本次功能在保留微信 `4.0.5.15`、`4.1.9.30` 私聊能力的前提下，增加一个保守的群聊入口。群聊必须同时满足精确群白名单、具体文字消息明确 @ 机器人、OCR 唯一识别发送者三个条件才触发。不同成员独立收集明确 @ 的消息，共享群内最近 20 条启动后文字上下文，并通过单一回复队列操作微信窗口。

## Goals

- 支持白名单群 `测试群聊`，且只有明确 `@biubiubiu仿生人` 的文字消息触发回复。
- 可靠区分群成员，使交叉发言时不同成员拥有独立的 7 秒静默窗口。
- 让同一成员在 7 秒内发送的多条、且每条都明确 @ 机器人的消息合并为一次模型调用。
- 给模型提供同一群启动后最近 20 条、带发送者标记的文字上下文。
- 回复第一条气泡优先真正 @ 提问者，无法唯一选择时降级为可见文本 @。
- 保持现有私聊白名单、取消语义、持久化 Session、提示词文件、原始回复日志和双版本 UIA 行为不回归。

## Functional Requirements

### Configuration

- F1：新增 `wechat.allowed_groups` 字符串列表，与 `allowed_contacts` 完全独立，群名去除首尾空格后精确匹配。
- F2：新增 `wechat.self_names` 字符串列表，用于识别群消息中对机器人的明确 @；本次示例值为 `biubiubiu仿生人`。
- F3：启用微信机器人时，`allowed_contacts` 与 `allowed_groups` 至少一项非空；仅配置群聊时不得被现有私聊白名单校验阻止。
- F4：`allowed_groups` 非空时，`self_names` 必须非空；重复项、空字符串以及同时出现在私聊和群聊白名单中的同名会话必须明确拒绝。
- F5：`allowed_groups` 为空时不启用群聊扫描，也不加载群发送者 OCR，不影响现有私聊。

### Discovery, baseline and message observation

- F6：启动时为私聊和所有白名单群建立消息基线；启动前已有未读、历史 @ 和当前可见群消息不得触发回复，也不得进入群共享上下文。
- F7：群聊身份必须由当前会话标题及成员数量控件共同确认；搜索结果不唯一、标题不匹配或无法确认群类型时安全拒绝。
- F8：群会话行的微信原生 `[有人@我]`（含兼容语言标记）仅作为优先扫描的粗粒度信号，不能单独确定具体触发消息；机器人当前停留在群聊时即使没有该行标记，也必须能依据新气泡正文识别真实 @。
- F9：白名单群启动后新出现的可见文字消息都可用于构建共享上下文；图片、文件、语音、视频、分享卡片和无正文引用消息不在本次处理范围。
- F10：每条可见文字消息必须具有稳定去重标识、UIA 正文、边界坐标、方向和发送者状态；重复扫描不得重复入上下文或重复触发。

### Sender recognition and mention detection

- F11：消息正文必须由 UIA 读取，OCR 不得替代或改写正文。
- F12：群成员昵称使用聊天区域截图和 OCR 识别：先用正文与几何位置关联 OCR 文本行，再选择消息气泡正上方唯一且达到置信阈值的昵称。
- F13：OCR 无法加载、无法匹配正文、昵称缺失、候选不唯一或置信度不足时，发送者记为未知；未知发送者消息不得进入共享上下文、不得入队、不得触发回复。
- F14：发送者身份按群内显示昵称处理，不宣称获得微信账号 ID；同群同名成员无法安全区分时不得把候选视为唯一身份。
- F15：一条群消息只有同时满足以下条件才是触发消息：群在 `allowed_groups`、消息为入站文字、正文包含规范化后的 `@<self_name>`、发送者被 OCR 唯一识别。会话行 @ 标记可用于发现和提速，但其缺失不能否决当前已确认的新气泡。
- F16：匹配 @ 时必须兼容微信使用的 `\u2005`、不换行空格及 Unicode 规范化；不得用子串昵称或模糊匹配替代完整的 `@<self_name>`。
- F17：送入当前问题前只移除匹配到的机器人 @ 及其紧随空白，保留正文中对其他群成员的 @。

### Batching and queueing

- F18：群聊待处理批次以 `(conversation_name, sender_name)` 为键；群名已经过白名单、类型和唯一性校验，私聊仍按现有好友会话键处理。
- F19：群聊中只有每条自身明确 @ 机器人的合格消息才能创建或进入批次；同一成员未 @ 的补充消息不得被活动窗口吸附。
- F20：同一成员每加入一条合格消息，都重新开始该成员的 7 秒静默计时；其他成员消息不得重置、结束或污染该窗口。
- F21：静默到期后，批次按到期顺序加入现有全局 FIFO；同一群和不同群的微信 UI 发送操作不得并发执行。
- F22：群批次进入模型生成或发送后，新 @ 不得取消当前群回复；它必须进入新的独立窗口并排到已有回复之后。
- F23：现有私聊行为保持不变：同一好友的新消息仍可取消该好友正在进行的私聊回答。

### Shared group context and model input

- F24：每个白名单群在内存中维护启动后最近 20 条已确认发送者的文字消息，超过 20 条时删除最早消息。
- F25：共享上下文可包含未 @ 机器人的普通群消息，但这些消息只作为参考数据，永远不能自行触发模型调用。
- F26：群模型输入必须明确分为“群聊参考记录”和“当前需要回答的 @ 消息”，每条内容均标注发送者；提示词必须声明参考记录不是系统指令。
- F27：当前批次只包含同一发送者的合格 @ 消息；不同成员即使在同一群、同一时间段内也必须形成不同模型请求。
- F28：群聊模型状态不得恢复启动前群消息；本次不提供历史回溯能力。群回复依据仅为当前进程的 20 条滚动上下文、当前批次和固定提示词。
- F29：同一群的模型请求必须按全局 FIFO 串行执行，使共享上下文和发送顺序确定；不同成员不能互相取消。
- F30：群聊继续始终使用包内 `prompts/role.md` 与 `prompts/reply_policy.md`，并保留每次模型原始最终回复的控制台标签输出。

### Sending and mention fallback

- F31：发送群回复前必须重新搜索并唯一确认群名和群类型；不得仅凭当前前台会话发送。
- F32：第一条回复气泡优先在空输入框中输入 `@`，等待群成员菜单，按 OCR 昵称筛选并仅选择唯一精确匹配项，再追加正文发送。
- F33：真正 @ 的成员菜单未出现、超时、没有精确匹配或匹配不唯一时，必须清理未完成输入，并降级发送普通文本 `@发送者昵称` 加第一条回复正文。
- F34：后续模型气泡和独立来源消息不得重复 @ 提问者。
- F35：真正 @ 或文本降级都必须遵守现有空输入框检查、目标复核、发送后输入框清空验证和全局串行发送约束。
- F36：发生 @ 降级时控制台必须打印群名、发送者和不含消息正文的明确原因；不得重复调用模型或重复发送第一条气泡。

## Non-Functional Requirements

- N1：群聊默认关闭；只有 `allowed_groups` 非空才产生额外群扫描与 OCR 成本。
- N2：OCR 依赖放入 `wechat` 可选依赖，不得影响未安装微信功能的 Mewcode 核心环境。
- N3：OCR 模型在配置群聊时启动预热；依赖缺失或引擎不可用必须在监听前明确失败，不能运行一个看似正常但永远无法识别成员的群机器人。
- N4：截图只在本机内存中用于 OCR，不持久化图片、不上传远端、不写入会话档案。
- N5：群历史固定最多 20 条且仅在内存中保存，不新增群消息数据库表。
- N6：群名、成员昵称和消息正文可能出现在现有本地控制台与模型请求中；不得新增远端日志或额外日志文件。
- N7：所有 UIA 与 OCR 共享状态必须线程安全；微信窗口仍只有一个执行 UI 操作的临界区。
- N8：新增逻辑必须在无真实微信和无 OCR 模型推理的单元测试中可验证；几何匹配、批处理和发送降级应通过依赖注入或纯函数测试。
- N9：微信 `4.0.5.15`、`4.1.9.30` 的主窗口类、讲述人提示和现有控件选择器保持兼容；程序不得自动启动或控制 Windows 讲述人。

## Out of Scope

- 处理图片、文件、语音、视频、分享卡片或纯引用消息。
- 把没有 @ 机器人的后续消息并入成员批次。
- 读取启动前历史、滚动加载聊天记录或实现“总结上面的讨论” Tool。
- 获取微信账号 ID、解决同群完全相同昵称成员的唯一身份问题。
- 群成员黑名单、前缀触发、关键词触发、全消息自动回复或 `at_or_prefix` 多模式配置。
- 为不同群配置不同机器人昵称；本次所有白名单群共享 `self_names` 列表。
- 自动启动讲述人、Hook 微信进程或接入非桌面 UIA 协议。
- 群图片理解、文件下载、语音识别以及真实 @ 之外的复杂富文本编辑。

## Acceptance Criteria

- AC1：示例配置中的 `allowed_groups` 为 `测试群聊`、`self_names` 为 `biubiubiu仿生人`；群配置为空时私聊完整可用。
- AC2：启动基线包含旧 @ 时不产生事件、不填充群上下文；启动后新消息才进入观察链路。
- AC3：`测试群聊` 中张三发送 `@biubiubiu仿生人 A` 可触发；非白名单群、普通消息、附件、未知发送者或仅有会话行 @ 标记均不触发。
- AC4：张三与李四交叉发送合格 @ 时分别维护 7 秒窗口；张三的新 @ 只延长张三窗口，最终形成两个独立 FIFO 批次。
- AC5：活动窗口内张三发送不含机器人 @ 的消息时，它不进入张三当前批次；但发送者可信时可进入该群最近 20 条参考上下文。
- AC6：第 21 条可信文字消息到来后，滚动上下文只保留最近 20 条，并为每条保留发送者标签与原始 UIA 正文。
- AC7：模型收到的当前问题已移除机器人 @，仍保留其他 @；参考上下文与当前问题拥有清晰边界，原始最终回复仍打印一次。
- AC8：群回复生成期间收到新 @ 不取消当前回复；私聊同好友新消息的原有取消测试继续通过。
- AC9：第一条回复在成员菜单唯一匹配时产生真正微信 @；菜单失败或不唯一时只发送一次文本降级版本，后续气泡均不重复 @。
- AC10：发送前群名或群类型复核失败时不发送；同名搜索结果不唯一时安全拒绝。
- AC11：OCR 正文匹配、昵称几何匹配、低置信拒绝、未知发送者拒绝和不持久化截图均有自动化测试。
- AC12：现有微信私聊、双版本 UIA、提示词、原始回复日志、信息工具和全量测试无新增失败。
