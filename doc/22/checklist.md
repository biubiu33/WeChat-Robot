## Implementation Completeness

### Detection and trigger gates

- [ ] C1（AC1）：扁平引用气泡被拆成当前问题、被引用者、引用类型和一层预览；模型用户消息使用清晰结构区分这些字段（验证：UIA parser 与 Bot Prompt 测试检查精确字段和一次 Runtime 调用）。
- [ ] C2（AC2）：白名单私聊只有“引用 + 非空当前问题”才触发；空当前问题不会产生默认说明、Driver 调用或模型请求（验证：私聊空引用负例检查三个调用计数均为 0）。
- [ ] C3（AC2）：引用前普通消息 A、引用 B、引用后普通消息 C 依次形成三个独立意图，FIFO 顺序为 A → B → C；B 仍能看到此前私聊 Session（验证：受控时钟队列测试及 Runtime 请求快照）。
- [ ] C4（AC3）：白名单群只有“文字/图片引用 + 当前明确完整 @ + 唯一 OCR 发送者”才触发，首条回答定向 @ 当前提问者（验证：群 Bot/Driver 集成测试检查一次物化、一次模型调用和一次 `send_group_first`）。
- [ ] C5（AC4）：群聊未 @、@ 只存在于引用预览、@ 只存在于图片内容、OCR 发送者为空或群不在白名单时，引用不被定位、图片不被读取、模型不调用、消息不发送（验证：参数化负例的所有下游 spy 均为 0）。
- [ ] C6：群聊 `strip_self_mention()` 只移除当前问题中的机器人 @，保留当前问题内对其他人的 @，且不读取引用内容决定触发（验证：Driver 当前文字门禁测试）。
- [ ] C7：启动前已可见的引用只进入观察基线，后续相同快照不触发回复或上传（验证：基线前后重复扫描，事件和模型调用均为 0）。
- [ ] C8：非白名单会话中的引用不得被打开、定位、截图、编码、持久化或上传（验证：Bot/Driver 白名单边界测试检查所有阶段 spy 为 0）。

### Reference identity and context

- [ ] C9（AC6）：引用当前提问者、其他群成员、私聊好友和机器人自己的文字时，被引用者名称均准确进入结构化 Prompt（验证：参数化发送者测试检查 Provider 请求）。
- [ ] C10（AC6）：被引用原消息本身也是引用时，只使用该原消息的当前正文；不会出现第二次“定位到原文位置”动作（验证：嵌套引用测试检查解析结果与定位调用次数为 1）。
- [ ] C11（AC5、AC6）：相同预览对应多个原文候选、被引用者变化或 runtime id 重用时安全拒绝，不按距离或第一个候选猜测（验证：歧义 UIA fixture 检查无点击错误候选和无模型调用）。
- [ ] C12：相同当前问题引用不同发送者或不同预览时产生不同事件身份；定位过程中再次看到当前引用和原消息不会重复触发（验证：事件指纹、稳定快照和 Store 去重测试）。
- [ ] C13（AC1、AC2）：私聊 JSONL 中引用关系以可读文本保留，恢复后仍能看到当前问题、被引用者、类型和引用内容；既有 Session 历史只用于消歧（验证：归档恢复后的下一次 Provider 请求快照）。
- [ ] C14：群聊最近 20 条上下文保留文字引用的实际内容与降级状态；图片引用只保留发送者、尺寸、哈希、降级和“数据已释放/未读取”占位（验证：群历史更新测试检查条目内容、长度上限和后续请求）。

### Referenced text resolution

- [ ] C15（AC5）：能够定位唯一原文时使用完整原文，结果标记为 `wechat_locate_original` 且回答不附加“不完整”披露（验证：定位成功 UIA/Bot 集成测试）。
- [ ] C16（AC5）：定位菜单缺失、原文安全不可达或唯一候选不存在，但预览可读时使用预览，并要求最终回答明确说明内容可能不完整（验证：预览降级测试检查 Prompt 和可见回答约束）。
- [ ] C17（AC5）：完整原文与预览均为空时模型调用为 0，只发送一次“引用内容暂时没读出来”类提示（验证：空文字故障注入检查调用与发送次数）。
- [ ] C18：引用原文定位后被识别为图片时转入图片流程；被识别为文件、语音、视频或分享卡片时转入不支持流程，不把标题当普通文字猜测（验证：原控件类型重分类测试）。
- [ ] C19：当前结构化引用单独超过模型预算时，在 Session 写入和 Provider 调用前拒绝，不静默截断，只发送一次复制关键段落提示（验证：小 context window 测试检查档案字节、Session 绑定和 Provider 请求均未增加）。

### Referenced image acquisition and validation

- [ ] C20（AC7）：引用区域能够打开大图时只执行第一级大图路径，截图后安全关闭查看器并恢复原会话，结果 `degraded=False`（验证：查看器生命周期与调用顺序测试）。
- [ ] C21（AC7）：引用区域大图安全失败后才执行“定位原图 → 原图大图”，成功后不执行缩略图路径（验证：严格三阶段 spy 顺序为 quote viewer → locate → original viewer）。
- [ ] C22（AC7）：前两级安全失败后截取引用缩略图，结果 `degraded=True`，最终回答明确说明可能不是完整原图（验证：缩略图故障注入检查边界、Prompt 和可见回答约束）。
- [ ] C23（AC7）：三阶段都安全失败时模型调用为 0，只发送一次图片失败提示（验证：三级失败 Bot 集成测试）。
- [ ] C24（AC8）：引用图片实际内容为 JPEG、PNG、GIF 或 WebP 时接受；损坏、未知格式、单边超过 8192 像素或原始数据超过 32 MiB 时调用模型为 0且只提示一次（验证：复用图片校验参数化测试与 Bot 集成测试）。
- [ ] C25（AC8）：有效图片作为当前用户消息的 Base64 Data URL、`detail=original` 发送，当前问题和图片属于一次请求；不产生外部 URL、Files API、压缩、缩放或转码（验证：Provider 请求快照及 Base64 解码字节比对）。
- [ ] C26：有当前问题的引用图片只按问题分析，不额外触发默认图片描述；图片或视觉调用失败时不重试、不调用其他模型、不按文件名/历史猜测（验证：Bot 调用计数和失败 Provider 测试）。

### Private and group image lifecycle

- [ ] C27（AC9）：私聊引用图片在好友 JSONL 中只保存一份明文 Base64，并同时保存实际格式、尺寸、字节数、哈希、detail、时间和降级状态（验证：Session JSONL 往返及 Base64 出现次数）。
- [ ] C28（AC9）：私聊引用图片成为最新活动批次，随后三个纯文字好友回合均重新提供同一图片，第四回合不再携带；档案不复制 Base64（验证：四回合 Provider 请求和 JSONL 检查）。
- [ ] C29（AC9）：新图片批次替换旧活动批次，重启恢复剩余额度，256 MiB 配额优先清理最早非活动 Base64并保留元数据占位（验证：替换、重启和小配额 repository 集成测试）。
- [ ] C30：私聊引用图片的临时大图/缩略图在成功、失败、取消、超时和发送异常后均不存在，但 Session Base64 保持可恢复（验证：参数化临时目录与档案双检查）。
- [ ] C31（AC10）：群聊当前 Provider 请求能够看到引用图片，但该群任务产生或修改的 JSONL、群历史、缓存和后续 Provider 请求都不含该 Base64（验证：群临时 archive transform 测试使用哨兵 Base64 扫描相关持久路径和下一请求）。
- [ ] C32（AC10）：群聊引用图片在成功、失败、取消或超时后临时文件与临时 Session 均被删除（验证：参数化群生命周期测试检查会话目录和临时路径）。
- [ ] C33（AC10）：群成员对引用图片继续普通 @ 追问时不携带旧图；只有再次引用该图片并明确 @ 才产生新的视觉请求（验证：连续三事件集成测试检查图片请求布尔序列）。
