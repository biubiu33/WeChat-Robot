# 上下文管理与记忆系统 Spec

## 背景

MewCode 当前只在进程内保存会话消息，TUI 只追加实时组件。长时间任务会因工具结果和历史持续累积而接近模型窗口；进程退出后，项目知识、用户偏好和会话进展也无法恢复。本章将会话档案与模型 Prompt Context 分离，在有限 Token 预算内保持长任务可持续执行，并在新会话或恢复会话时注入项目知识与用户偏好。

## 目标

- TUI 可重放完整、原始的会话档案，模型则使用独立且可压缩的 Prompt Context。
- 工具大输出优先归档为项目内缓存文件，避免挤占上下文，同时保留可重新读取的路径。
- 接近上下文窗口时自动压缩历史；用户可手动触发压缩且不会改写 TUI 档案。
- 通过项目指令、会话恢复和自动记忆，让新会话能够延续项目知识、用户偏好与未完成工作。
- 在异常、文件损坏、长时间间隔和过期会话等情况下安全降级，不阻塞正常对话。

## 功能需求

- **F1: 双视图会话管理**
  每个会话同时维护完整的会话档案与独立 Prompt Context。会话档案是唯一事实来源，保存用户可见的原始消息、助手回复、工具调用、工具结果、归档引用、标题更新和压缩检查点；Prompt Context 由档案与压缩检查点重建，仅用于 API 请求。压缩不得改写用户可见的历史或用户消息原文。压缩检查点只描述模型上下文中被摘要替换的范围、正式摘要与保留边界，不得替代或删除任何可见档案事件。

- **F2: 工具结果预防归档**
  每次 API 请求前，系统检查 Prompt Context 中的工具结果。单个工具结果超过 16,000 字符时归档；同一条工具结果消息累计超过 32,000 字符时，按结果大小从大到小继续归档，直到低于限制。归档后 Prompt Context 仅保留预览、产物路径及重新读取提示，TUI 档案保留完整事件与归档关联。

- **F3: 上下文压缩**
  每次 API 请求前，在预防归档后评估累计 Prompt Context。自动压缩在估算可用窗口保留 13,000 Token 安全余量；手动 `/compact` 压缩保留 3,000 Token 安全余量。Provider 可配置 `context_window`，未配置时按 1,000,000 Token 估算。压缩时保留最近约 10,000 Token 或至少五条消息的原文，其余早期内容由摘要替换。

- **F4: 摘要安全与连续失败保护**
  摘要请求复用当前会话选定的 Provider 与模型，禁止工具调用。模型必须先产生一次性分析草稿，再输出正式摘要；草稿不写入档案或 Prompt Context。正式摘要固定包含：主要请求和意图、关键技术概念、文件和代码段、错误和修复、问题解决过程、所有用户消息、待办任务、当前工作、可能的下一步。其中所有用户消息必须原文保留，“当前工作”必须最详细。压缩后向 Prompt Context 注入边界提醒，要求模型需要文件细节时重新读取，不得依据摘要臆测代码。连续三次自动摘要失败后，自动压缩在当前会话熔断；用户可用 `/compact` 手动重试，成功后恢复自动压缩。

- **F5: 项目内持久化布局与清理**
  会话档案、工具产物和项目级自动记忆分别保存在项目 `.mewcode` 下的 `sessions`、`cache` 和 `memory` 位置。工具产物按会话归属存放。上述目录默认加入版本控制忽略规则；清理超过 30 天的会话时，同时清理其对应缓存目录和项目级会话数据。清理在启动后和打开恢复会话列表前执行。

- **F6: JSONL 会话档案与恢复**
  每个会话使用一个 JSONL 档案并按事件追加，崩溃时最多损失末尾不完整记录。会话 ID 固定为 `YYYYMMDD-HHMMSS-xxxx`，其中前半部分为本地创建时间，后半部分为四位随机十六进制字符，用于避免同秒冲突。每个档案事件必须具有事件类型与写入时间；可见消息事件还须保留角色、正文以及适用的工具调用或工具结果，首条用户消息须记录当时选定的模型，以支持会话列表展示。异步标题生成结果必须作为标题更新事件写回同一档案；工具归档与压缩必须作为独立事件写回同一档案。

  不维护独立 meta 文件；会话标题、最后活动时间和消息数均通过扫描档案取得。恢复时跳过坏行；TUI 始终按完整的可见事件重放，不得从压缩检查点之后才开始显示。Prompt Context 则使用最新完整压缩检查点与其后的相关事件重建；没有可用检查点时从完整档案重建。未配对工具调用从不完整位置截断；超出 Prompt Context 预算时先尝试压缩；距上次活动超过七天时向模型注入时间跨度提醒，要求重新检查可能变化的工作区状态。

- **F7: 会话标题与 `/resume`**
  首条用户消息提交后，异步使用当前会话 Provider/模型生成简短标题，并将结果以标题更新事件写回 JSONL；失败时以该消息的清理截断文本生成并写回回退标题。`/resume` 通过扫描档案中最新的标题更新事件取得标题；兼容缺少标题事件的历史档案时，以首条用户消息的清理截断文本作为显示回退。列表显示标题、会话 ID、最后活动时间和消息数，并为当前选中会话提供可点击删除操作。删除须移除该会话 JSONL 及同 ID cache 目录；项目级与用户级长期记忆不得删除。选择会话后，TUI 从 JSONL 重放用户可见档案，并重建 Prompt Context。长档案可按需加载较早部分，避免一次创建过多 TUI 组件。

- **F8: 项目指令**
  进程启动时加载一次三层手写项目指令：项目根、项目 `.mewcode` 与用户 `.mewcode` 中的 `MEWCODE.md`，并在整个进程生命周期内缓存。`/resume` 与后续请求复用该缓存，不重新读取磁盘；修改指令文件须在重启 MewCode 后生效。项目根优先级最高，随后为项目 `.mewcode`，用户级最低；高优先级内容在系统上下文中靠前。指令支持 `@include`，最多嵌套五层，并使用已访问集合阻止循环。项目层引用只能停留在项目根内，用户层引用只能停留在用户 `.mewcode` 内，不允许跨根或跳出信任根。

- **F9: 自动记忆与索引**
  每轮 Agent Loop 自然结束且最终回复没有工具调用时，异步使用当前会话 Provider/模型更新自动记忆，且该请求禁止工具调用。模型负责去重和分类，笔记分为：用户偏好（`user`）、纠正反馈（`feedback`）、项目知识（`project`）和参考信息（`reference`）。前两类存储在用户级记忆位置，后两类存储在项目级记忆位置。每条笔记使用带 frontmatter 的 Markdown；用户级与项目级各维护一个可注入的索引。索引在请求前注入上下文，最多 200 行或 25KB；达到任一上限时，由同一异步 LLM 更新任务合并重复内容、保留高价值且近期有效条目，原始笔记不删除。

- **F10: TUI 与隐式上下文边界**
  项目指令、记忆索引、时间跨度提醒、压缩边界提醒和摘要草稿属于模型上下文，不伪装为用户或助手消息。TUI 可显示“已压缩上下文”等状态通知，但重新打开会话时必须显示档案中的原始用户可见事件，而非摘要替代内容。

## 非功能需求

- **N1: 上下文安全**
  用户原始消息在档案和摘要中均不被改写；归档与压缩失败不得丢失会话档案或阻塞当前请求。
- **N2: 崩溃韧性**
  档案追加、坏行跳过、工具调用截断和过期清理不得使应用无法启动或恢复其他会话。
- **N3: 隐私与版本控制**
  会话、缓存和自动记忆默认不进入 Git；背景标题、摘要和记忆请求使用当前已选择的 Provider，且不回显敏感内容。
- **N4: 交互响应性**
  标题与自动记忆任务在后台执行，不阻塞 TUI、Agent Loop 或下一轮用户输入；失败有确定的降级行为。
- **N5: 兼容性**
  既有 Provider、MCP、权限、工具调用、规划模式、取消、流式输出和提示缓存行为不退化。
- **N6: 近似估算**
  不引入精确 tokenizer；Token 预算使用最近 API usage 锚定，并仅对新增内容按字符数近似估算。

## 不做的事

- 精确 tokenizer、学习型摘要策略或摘要质量优化。
- 向量数据库、RAG 检索、团队记忆同步或跨项目自动检索。
- 会话 meta 文件、独立 Prompt Context 快照文件或其他需与 JSONL 同步的状态文件。
- 修改 TUI 档案中的历史消息、用摘要替换用户可见内容，或将隐式上下文伪装为聊天消息。
- 自动重试无限失败的摘要、标题或自动记忆请求。
- 超出信任根的项目指令引用，以及超过五层的 `@include` 嵌套。

## 验收标准

- **AC1: 双视图一致性**：压缩前后，重新打开会话的 TUI 原始用户/助手/工具事件保持一致；下一次 API 请求只使用压缩后的 Prompt Context。
- **AC2: 工具结果归档**：单条超过 16,000 字符或单消息累计超过 32,000 字符的工具结果归档，Prompt Context 留下预览、路径和重新读取提醒，原始档案可追溯。
- **AC3: 自动与手动压缩**：自动压缩使用 13,000 Token 余量，`/compact` 使用 3,000 Token 余量；近期消息按约 10,000 Token 或至少五条原文保留；摘要包含九个固定部分和原始用户消息。
- **AC4: 摘要安全**：摘要、标题和自动记忆请求无工具调用；摘要草稿不持久化；连续三次失败后自动压缩熔断，手动成功压缩后恢复。
- **AC5: 档案恢复与清理**：新会话 ID 符合 `YYYYMMDD-HHMMSS-xxxx` 格式；JSONL 可扫描得到首条消息的模型、最新标题、最后活动时间和消息数。JSONL 坏行被跳过，不完整工具调用被截断；超过七天注入时间跨度提醒；超过三十天的会话及缓存被清理；恢复不依赖 meta 文件。
- **AC6: `/resume` 体验**：异步生成的标题或其清理截断回退会写入 JSONL，列表可由 JSONL 扫描显示标题、ID、时间和消息数。即使档案已有压缩检查点，恢复后 TUI 仍重放完整可见档案；Prompt Context 则按最新有效检查点和后续事件、并按预算重建。
- **AC6.1: `/resume` 删除会话**：选中会话的删除操作会移除 JSONL 档案及同 ID cache 目录，并立即从列表消失；项目级和用户级 memory 目录及其中笔记保持不变。
- **AC7: 项目指令安全加载**：三层 `MEWCODE.md` 在进程启动时按优先级加载并注入；进程运行期间修改文件不影响后续请求或 `/resume`，重启后才生效。合法五层以内 include 生效，循环、跨根和跳出根目录引用被拒绝且不会阻塞启动。
- **AC8: 自动记忆**：四类笔记进入正确的用户级或项目级位置；索引在请求前注入；超过 200 行或 25KB 后被压缩，原始笔记保留。
- **AC9: Git 与 UI 边界**：会话、缓存和项目记忆默认被 Git 忽略；隐式上下文不作为用户/助手消息显示，TUI 仅显示可见档案和必要状态通知。
- **AC10: 不退化**：全量测试、编译、静态检查和格式检查通过；既有对话、工具、MCP、权限、流式、取消和规划测试保持通过。
