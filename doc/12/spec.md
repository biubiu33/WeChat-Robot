# 子 Agent 与后台任务 Spec

## 背景

MewCode 当前能通过 Skill fork 运行隔离任务，但只能传入参数、同步等待摘要，且没有统一的角色目录、后台任务控制、父历史 Fork、任务通知或独立运行时状态。主 Agent 因而无法按任务性质稳定委派探索、规划或通用工作，也无法在长任务执行期间继续与用户协作。

本功能提供一个始终可见的统一 Agent 工具。它既能以预定义角色从干净上下文启动，也能 Fork 父对话历史；子任务独立运行并由主 Agent 统一管理结果、权限升级和后台生命周期。

## 目标

- 让主 Agent 能通过稳定的 Agent 工具委派定义式或 Fork 式子任务。
- 隔离子 Agent 的对话、权限账本、文件读缓存和用量统计，同时复用必要基础设施。
- 支持非阻塞后台执行、任务完成通知、查询、停止和续派。
- 让角色能力、工具范围、模型选择、轮次与权限模式可声明、可覆盖且可验证。
- 保持现有 Skill fork、权限、Hook、Provider、MCP、会话与工具行为兼容。

## Functional Requirements

- F1: 主 Agent 始终看到一个名称和参数结构固定的 Agent 工具。调用必须提供任务提示与简短描述；可选提供角色名、模型档案、后台标记和任务名称。角色名为空时走 Fork 路径，非空时走定义式路径。角色目录的增删不得改变该工具的定义。

- F2: 定义式子 Agent 使用空白对话和所选角色的完整指令启动。Fork 式子 Agent 克隆父对话历史，在尾部加入带任务的 Fork 约束，并强制进入后台。Fork 首次请求应最大化复用父对话的提示词缓存前缀。

- F3: 角色定义采用带 YAML frontmatter 的 Markdown 文件，包含规范角色名、说明、可用工具、禁用工具、模型档案、最大轮次、权限模式和默认后台策略。角色名按小写 kebab-case 存储和覆盖，调用时大小写不敏感。项目、用户、内置和预留插件来源按项目高于用户、高于内置、高于插件的顺序覆盖；本期插件来源为空。单个项目或用户定义无效时给出诊断并跳过，内置定义无效则视为程序错误。

- F4: 主 Agent 的动态环境仅提供当前角色的名称和一句说明，使模型能选择角色；角色正文仅在对应子 Agent 启动时加载，不能泄露给主对话或其他角色。

- F5: 每个子 Agent 具有独立的对话、会话级权限账本、文件读缓存、用量和 Hook 会话状态。LLM 客户端、Hook 规则目录、文件系统和工具注册表可共享。子 Agent 创建时快照父会话级精确授权；之后父子会话级授权互不同步。

- F6: 子 Agent 以 RunToCompletion 方式运行：任务直接作为消息加入子对话；模型不再请求工具时返回最后一条 assistant 文本；达到角色轮次上限时返回最后文本并报告轮次上限错误。子 Agent 不得以对话方式向用户提问、等待用户输入或自行再派生 Agent。

- F7: 子 Agent 的工具调用沿用工具前置 Hook、权限、执行和后置 Hook 的基本顺序。它触发消息前、工具前、工具后、停止和通知等执行相关 Hook，但不触发用户会话的开始、结束、恢复或提交事件。每个子 Agent 使用独立 Hook 会话状态。

- F8: 子 Agent 权限按以下顺序判定：创建时快照的父会话级精确授权、持久权限规则、角色权限模式、再升级到主 TUI 批准。权限升级不是对话式追问；子 Agent 暂停，由主 TUI 标识来源并转发用户的批准或拒绝结果后继续。仅用户明确选择 Allow Forever 时，才允许写入共享的永久规则；本次和会话级授权只留在相应 Engine。

- F9: 子 Agent 工具集合必须经过多层收窄：全局子 Agent 禁止列表、后台白名单、角色黑名单和角色白名单依次生效。Agent、任务查询、任务停止和任务续派控制工具永远不得对子 Agent 可见。子 Agent 可加载 inline Skill，但不得执行 fork Skill；任何嵌套尝试必须返回结构化拒绝。

- F10: 子 Agent 的文件读缓存只在本 Agent 内存中有效。重复读取未变化文件可复用缓存；读取前必须依据文件更新时间和大小校验新鲜度。成功写入或编辑后，写入者自身的相应缓存必须失效；父子及并行任务之间不得共享缓存。

- F11: 定义式子 Agent 可前台或后台执行：调用显式请求后台、角色默认后台、前台运行超过 120 秒，或用户在执行/流式阶段按 ESC 时，均进入后台。后台功能被全局关闭时，所有定义式子任务强制前台，Fork 请求返回明确错误。权限批准框中的 ESC 等价于拒绝本次批准，而不是转后台。

- F12: 后台任务保存任务 ID、可选名称、状态、子 Agent 与对话、任务文本、最终结果或错误、时间、取消控制、用量、工具调用数和最近活动。任务在主进程生命周期内保留，即使已完成、失败或取消；重复名称只把名称索引更新为最新任务，任务 ID 始终精确引用原任务。

- F13: 后台任务完成、失败或取消后，主 Agent 的下一次模型请求收到一次不可见、非归档的 `<task-notification>` 系统提醒。提醒被消费后移除，不写入用户可见对话、会话档案、长期记忆或压缩历史。任务详细结果持续可由任务查询工具取得。

- F14: 主 Agent 独占任务列表、任务详情、停止和按名称发送消息四个管理工具。发送消息只能命中仍保留且已完成的子 Agent；消息追加到该子对话后重新在后台运行，并保留原任务身份。

- F15: 模型档案由用户配置决定。`inherit` 复用父 Agent 的 Provider；角色或调用指定的档案名必须在配置中存在，否则 Agent 工具返回结构化模型不可用错误。实现不得硬编码模型提供商或模型 ID。

- F16: 内置提供 `general-purpose`、`explore` 与 `plan` 三个角色：通用角色允许完整的父级可用能力并继承模型；探索角色仅用于只读探索并使用 `haiku` 档案；规划角色仅用于只读规划并采用规划权限模式。现有 Skill fork 必须复用同一套子 Agent 启动和执行语义，同时保持其既有的用户可见结果行为。

## Non-Functional Requirements

- N1: 主 Agent 工具列表在角色目录变化、子 Agent 启动或完成时保持不变。
- N2: Fork 路径不得因克隆历史而破坏 Provider 所需的工具调用消息关联；父历史中的未完成调用必须被安全补全后再用于 Fork。
- N3: 后台子 Agent 的异常、取消或超时不得中断主 Agent、主 TUI 或其他后台任务；失败必须记录为可查询状态。
- N4: 子 Agent 不能通过直接 Agent 工具、任务控制工具、fork Skill、提示词注入或工具白名单绕过嵌套限制。
- N5: 黑名单、文件路径沙箱、参数校验和显式永久权限规则的安全语义在子 Agent 中继续有效。
- N6: 子 Agent 的用量、缓存和会话状态不得计入或污染主会话统计；主 Agent 仅通过任务结果、通知和显式任务工具接收子任务信息。
- N7: 完整功能不得导致现有 Provider、MCP、Skill、Hook、权限模式、审批、会话恢复、上下文压缩或 Slash 命令回归。

## Out of Scope

- Worktree 或其他文件系统隔离。
- 多 Agent 团队编排、自动协作拓扑或验证 Agent 开关。
- 后台任务跨会话或跨进程持久化。
- 真实插件加载；插件来源仅保留覆盖顺序接口。
- 子 Agent 输出的强制结构化 schema。
- 主动创建后台任务的额外工具，除统一 Agent 工具外的任务创建入口。
- 通过 Hook 实际运行子 Agent 动作。
- 将子 Agent 用量汇总进主会话状态视图。

## Acceptance Criteria

- AC1: 主 Agent 在角色目录为空、增加、删除或覆盖角色前后均只看到同一个 Agent 工具；同时能从环境目录选择有效角色。
- AC2: 定义式调用只接收角色指令和任务；Fork 调用继承父历史、附加 Fork 约束、强制后台且满足合法工具调用消息格式。
- AC3: 角色目录按规定来源覆盖、角色名大小写归一化、非法项目/用户文件诊断跳过、非法内置定义失败。
- AC4: 子 Agent 与父 Agent 的消息、会话授权、文件缓存、用量和 Hook 会话状态相互隔离；创建时存在的父精确授权可被子任务使用，之后新增授权不可见。
- AC5: 子 Agent 在无工具调用时返回最后 assistant 文本；在轮次上限时返回最后文本和明确错误；不会请求常规用户输入。
- AC6: 子 Agent 工具调用按父授权快照、永久规则、角色模式和主 TUI 升级链处理；Only Forever 跨边界持久化，批准框 ESC 等于拒绝本次。
- AC7: 所有子 Agent 都看不到 Agent 和任务控制工具；fork Skill 嵌套被拒绝，inline Skill 仍可按既有规则使用。
- AC8: 本地文件读缓存仅命中未变化文件，外部修改、写入和编辑后不会返回过期内容，也不会在父子之间共享。
- AC9: 显式后台、角色后台、120 秒超时、执行阶段 ESC 与强制 Fork 后台均产生可查询任务；后台关闭时按规定前台或报错。
- AC10: 任务完成、失败与取消均可查询并在进程存活期间保留；同名任务选择最新项，按 ID 仍可访问旧项；完成子 Agent 可被续派。
- AC11: 每个终态后台任务向主 Agent 的下一次请求注入一次不可见通知，通知被消费后消失，详细结果仍可通过任务详情查询。
- AC12: 角色模型档案由配置解析，继承和不可用模型按规定处理；实现不依赖固定模型 ID。
- AC13: 三个内置角色可用，既有 Skill fork 复用统一子 Agent 能力，现有核心回归测试继续通过。
